## Local integration seam

Cloudvore should not retrofit seventy launchers independently. After local review, install the exact
candidate outside the doctrine checkout and add one project-owned adapter immediately before the
single canonical provider-spawn seam. The adapter must:

1. verify the expected manifest SHA and every installed file before reading capacity or creating a
   provider process;
2. derive the opaque Anthropic quota domain from the already proved CLI/desktop account-parity
   evidence without persisting a raw account identifier;
3. translate the already hub-authorized frozen `PROVIDER_REQUEST v1` slice into a capacity request;
   a capacity request cannot create work or replace router authorization;
4. require a fresh normalized capacity observation, acquire the host-wide lease, then revalidate
   router plan, subject, worktree, claim vacancy, provider adapter manifest, and effective profile;
5. launch only the exact captured child process tree and enforce wall, turn, and context ceilings;
6. normalize usage, classify quota/session-limit output, write a non-green bounded terminal on
   meter or process-control ambiguity, and release the lease in every terminal path;
7. refuse every unattended direct provider spawn that bypasses the canonical seam. Attended owner
   foreground use remains explicit and audited, not silently intercepted;
8. preserve the existing no-dispatch provider router, two-class review gate, product test bar,
   lifecycle writer, landing, rollback, push, and release boundaries unchanged.

The account-wide gate is additive: router eligibility answers whether a profile may perform a
role; capacity admission answers whether that already-authorized profile may start now. Neither
predicate substitutes for the other.

## Activation ladder

1. **Observe only:** normalize existing session artifacts and compare derived totals to local source
   evidence. No launcher change.
2. **Shadow decide:** create requests and decisions, but do not use them to launch or block. Measure
   false holds and forecast error against completed slices.
3. **Background enforce:** route scheduled/background model roots through the broker, default
   single-flight, with an emergency rollback to the current launch seam. Owner foreground remains
   unchanged.
4. **All automatic roots:** deny direct unattended provider spawns only after process-tree,
   crash/expiry, stale-meter, account-rotation, reset-herd, budget-pause, and rollback drills pass.
5. **Optional foreground reservation:** expose an owner-attended preflight; never automate account
   rotation or bypass hard-cap/staleness/concurrency controls.

No model or effort downgrade is part of this ladder. A proposed Sonnet, Terra, Luna, Kimi, Grok, or
lower-effort route enters only through Cloudvore's existing exact role-cell benchmarking and
independent-review requirements.

## Required negative proofs

- deleting the canonical broker call makes a production-wiring test fail;
- deleting manifest verification, snapshot freshness, domain concurrency, reserve, reset quiet,
  process-tree cleanup, requested/effective identity comparison, or non-green budget terminal makes
  a mutation fail;
- two Cloudvore/Conjugal contenders on the same domain admit at most one, while two deliberately
  different account domains may both admit;
- a rotated account invalidates the prior domain epoch and never inherits its health latch;
- a live child at lease expiry blocks a successor rather than allowing overlap;
- a model-powered idle, registration, duplicate-detection, or heartbeat call is mechanically
  impossible;
- all current provider-router tests and the project-required product bar remain green; and
- rollback restores the exact prior launch seam without deleting local usage evidence.

Cloudvore posts `ADOPT(...)` only after those local proofs. Until then it should post
`DISTINGUISH(PENDING_LOCAL_ADAPTER_AND_DRILLS)` and retain this packet as candidate data.
