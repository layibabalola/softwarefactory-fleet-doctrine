# 2026-08-18 shared Claude-capacity incident

**Status: measured local incident summary / candidate design input / no provider or project
authority.** Raw transcripts, credentials, account identifiers, and session files remain local and
are not reproduced here.

## Time and consumption

The five-hour meter was observed at 43% at 09:37 CT, 79% at 09:52, and 100% at 10:07. The directly
observed 43%→100% drain took 30 minutes. The first dominant post-reset session began about 09:31,
so the inferred usable interval from launch to exhaustion was about 36 minutes, not five hours.
The two dominant session wall spans were 35.6 and 16 minutes and overlapped.

The local aggregate contained 104 requests, approximately 10.6 million cache-read input tokens,
351 thousand cache-create input tokens, and 182 thousand output tokens. The dominant Cloudvore
session made 71 requests, read about 7.65 million cached tokens, emitted about 124 thousand output
tokens, and reached roughly 179 thousand context tokens. The overlapping Conjugal dead-man session
made 30 requests, read about 2.86 million cached tokens, emitted about 57.9 thousand output tokens,
and reached roughly 144 thousand context tokens. These native fields describe workload shape; they
do not claim Anthropic's undisclosed subscription-meter formula.

## Mechanism

No single cause explains the slope. The mutually reinforcing causes were:

1. two concurrent `claude-opus-5` maximum-effort roots shared one account allowance while each
   project enforced only a repo-local mutex;
2. both roots retained very large contexts and repeatedly processed those contexts through long
   agentic loops;
3. Conjugal scheduled Opus every 20 minutes and Fable every 15 minutes at maximum effort, including
   model-bearing supervision paths that did not always have productive work;
4. Cloudvore retained 70 Claude launch surfaces, 63 explicitly maximum-effort, with no common
   account-wide usage preflight; its existing provider router was plan-only and launchers could
   bypass it;
5. the reset created a launch herd: the dead-man root started about six minutes after reset while
   Cloudvore was already active;
6. one refusal parser did not recognize the exact “session limit” reset wording, delaying a clean
   `QUOTA-DORMANT(reset_eta)` transition;
7. other projects reported duplicate ignition, orphan heartbeat writers, account-rotation fanout,
   model-powered registration/idle checks, and unbounded background or subagent loops as the same
   defect family.

Cached input is relevant but should not be misread. Anthropic documents that cache-read tokens are
part of total input context even when they are billed or rate-limited differently. The incident
therefore supports a context/turn/concurrency diagnosis, not the claim that every cached token
counted one-for-one against the subscription window.

## Prevention decision

The fleet's existing `metrics/README.md` already ratified this doctrine repository as the single
data plane and explicitly rejected a second metrics repository. Preserve that ruling:

- live balances, domain fingerprints, detailed session events, credentials, queues, locks, and
  leases remain machine-local;
- versioned contracts, conformance cases, release hashes, redacted aggregate evidence, and each
  project's `ADOPT(reference)` or `DISTINGUISH(reason)` finding travel through this repository;
- projects never execute mutable bus bytes. They review and install an exact hash-pinned release;
- metrics never become launch, lifecycle, review, landing, or release authority.

The first preventive policy is account-domain single-flight, a 15-minute background reset quiet
period, fresh-meter requirement, per-priority reserve, and 10–20 minute bounded slices. Separate
provider accounts intentionally receive separate quota-domain ids and may run in parallel, but
they remain the same provider independence class unless separately proved otherwise.

Capability is preserved by reducing deterministic waste first. Registration, liveness, evidence
joins, deduplication, hashing, compaction decisions, and idle checks are model-free. Model or effort
changes occur only through the existing per-project role-cell non-inferiority protocol. Budget
stops are `PAUSED_BUDGET` with a compact checkpoint and earn no completion credit.

## Project disposition request

Cloudvore, Conjugal, MLV App, AudioMile, Agent Bridge, and other fleet members should publish one
row in their own `specs/<project>.md` after local review:

- `ADOPT(reference, exact release hash, local authority map, tests, activation state)`, or
- `DISTINGUISH(reason, local counterevidence, replacement control)`.

An adoption must identify its quota-domain derivation, every provider-launch entry point, exact
account scope, local broker installation hash, capacity-observation source, bounded process-tree
wrapper, quality regression suite, negative/mutation results, activation date, and rollback. A
finding without those local proofs changes no live routing.
