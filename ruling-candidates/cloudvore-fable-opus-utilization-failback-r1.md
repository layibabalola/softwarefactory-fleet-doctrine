# Cloudvore exact-model Fable-to-Opus utilization failback R1

**OWNER-DIRECTED PROJECT PROPOSAL / ZERO RUNTIME AUTHORITY / NOT AN ACTIVATION RECEIPT.** The
owner directed Cloudvore to use paid Claude Opus capacity for real factory work when Fable is
exhausted, with a rolling operating target of at least five account-usage percentage points per
hour. This candidate publishes the resulting strategy for fleet adopt-or-distinguish review. It
does not itself launch a model, spend quota, grant a role, or move product/score authority.

## Routing trigger and evidence boundary

At every scheduling wake, derive Fable and Opus state only from durable provider terminals, exact
reset timestamps supplied by the provider, and live claimed processes. Prose, lane labels, old
PIDs, old percentage samples, and model visibility are pointers, not capacity evidence.

- A durable exact-Fable refusal, spent terminal, known-reset suppression, reset-unknown limit, or
  other typed unavailability makes Fable ineligible for new work. Never invoke Fable merely to
  reproduce a known refusal and never invent a reset.
- If exact Opus capacity is lawfully available, immediately assign the highest-value safe,
  independent, non-overlapping critical-path package. Eligible work includes falsification,
  diagnosis, package review, recovery review, and next-gate preparation. It excludes filler,
  replay, duplicate review, already-terminal work, and prompt splitting intended to inflate spend.
- Never send the same prompt to Fable and Opus. Never relabel Opus work as Fable. Every substitution
  carries `MODEL_CAVEAT/FABLE_DIVERSITY_NOT_DISCHARGED`; both models remain one Anthropic
  independence class and cannot supply two acceptance keys.
- Project admission, one-writer custody, exact unconsumed launch authority, review independence,
  and provider capacity are separate gates. One cannot substitute for another.

## Exact Opus credit

Every credited invocation requests the account-eligible exact identifier `claude-opus-5`, freezes
and independently audits a content-addressed one-shot package, and reserves one collision-free
claim/result/log/terminal namespace. The authoritative terminal must expose top-level
`modelUsage` proving exact Opus-major-5 and `firstParty`, with positive usage from that same run.
Requested and effective identities, account/quota-domain fingerprint without credentials,
session/process ancestry, prompt/input tuples, terminal tuple, tokens, cache traffic, cost, and any
provider reset are preserved.

A missing/mismatched effective model, absent first-party proof, malformed/ambiguous terminal,
source drift, namespace collision, tool-policy breach, or unavailable endpoint is a truthful HOLD
and earns zero Opus credit. Process exit is not PASS; activity is not a terminal. Never retry a
spent namespace or interrupt an active one-shot unless current fail-closed doctrine explicitly
authorizes it.

## Five-point rolling utilization target

While Fable is unavailable and lawfully usable exact Opus capacity exists, maintain a rolling
operating target of at least **5 account-usage percentage points per hour**. Establish window
endpoints only from authoritative account-usage observations obtained as part of useful work;
never invoke inference merely to sample or move the meter.

At each wake, compute observed percentage drain and the remaining hourly gap from those durable
observations. If the rate is below target and audited useful packages exist, advance enough of the
highest-value queue to recover the target. Parallel launches are allowed only when claims, outputs,
custody, and review subjects are disjoint. No quota is reserved speculatively for Fable while it is
ineligible.

The controller keeps a ready queue so packaging does not become the reason paid capacity sits idle:

1. current critical-path falsification or design review;
2. same-generation HOLD diagnosis and regression authoring;
3. independently reviewable recovery/package audit;
4. frozen next-gate preparation that removes real serialization.

Queue readiness requires a useful unresolved subject, immutable input manifest or isolated
snapshot, exact source rejoin, exclusive future paths, completed independent package audit, bounded
runtime/context, and a named durable terminal. Source READY, fixtures, or partial composition grant
no score, product, execution, or controller authority.

If percentage evidence is absent or stale, report `CANNOT_DERIVE_PERCENTAGE_RATE`; exact tokens,
cache traffic, or cost may be reported but never converted into an invented percentage. If the
target cannot be met because Opus is unavailable, a reset forbids use, no audited package exists,
work would collide, completion/review reserve would be endangered, or no useful work exists,
record the exact shortfall and the package-preparation or recovery action. The target never
authorizes synthetic burn, weakened review, duplicate work, unsafe concurrency, or work with no
plausible terminal.

## Reset and failback

An exact provider reset suppresses only the proved namespace/quota domain through that timestamp.
At the first scheduler wake at or after reset, physically rejoin the frozen successor package and
confirm future outputs remain absent before its single authorized invocation. Mere passage of time
does not prove capacity.

Returned Fable capacity never preempts a live Opus slice or transfers its claim. At the next new
slice boundary, re-derive both models and choose the best eligible model for the role. Fable may
resume preferred work only on fresh positive post-reset evidence. Opus remains eligible for later
work under the same useful-work and exact-credit rules.

content-addressed design review. Its authenticated terminal reported exact first-party
`claude-opus-5` usage of 2 input tokens, 18,037 output tokens, 460,794 cache-creation tokens, zero

regression before revision. That terminal proves useful Opus work and exact spend; it does **not**
prove a five-point percentage drain because the available account-percentage observation was stale.
