# Approach A v7.8 — Consolidated Design

## 0. Scope, families, key set, lanes

Approach A v7.8 folds Round F4's AdversarialLLM, agent-bridge and airmypc filings. The factory produces, verifies and adopts work on one shared Windows checkout, `C:\code\Conjugal`, using git refs and per-lane journals; no database, service installation or shared secret. Tier 1 implements; Tier 2 verifies and attests, publishing only immutable evidence; the reducer alone publishes authoritative Oracle state; Tier 3 adjudicates and changes policy; Tier 0 produces this design outside the factory (§12).

Luna and Sonnet are default implementers; Haiku supplies second-seat votes only. Families and eligibility are defined once, in `refs/oracle/state:policy.yaml`; an authorized bench profile, a §6 amendment scoped to one receiving bench, may narrow `second_vote_eligible` where that bench forbids Haiku certification:

```yaml
lane_family:
  CODEX:  [sol, luna, astra]
  CLAUDE: [opus, fable, sonnet, haiku]
keyholders: [sol, astra, opus, fable]          # family derived from lane_family
emergency_keys: {CODEX: <key_id>, CLAUDE: <key_id>}   # revocation only (§6)
second_vote_eligible: [sol, astra, luna, opus, fable, sonnet, haiku]
attestation_helpers:   # helper_id: §4; two per family
  - {alias: A-codex,   checker_digest: <genesis digest 1>, custody_principal: attest-codex,   family: CODEX}
  - {alias: A-third,   checker_digest: <genesis digest 2>, custody_principal: attest-third,   family: CODEX}
  - {alias: A-claude,  checker_digest: <genesis digest 3>, custody_principal: attest-claude,  family: CLAUDE}
  - {alias: A-claude2, checker_digest: <genesis digest 4>, custody_principal: attest-claude2, family: CLAUDE}
helper_floors: {A-codex: &f [sol, astra, opus, fable], A-third: *f, A-claude: *f, A-claude2: *f}   # floors able to start each helper; hosting confers nothing
adopt_mode: live-sol
adopters: [sol, sol-adopt]                     # §4
budget_mode: unrestricted                      # or throttled
```

`lane_family_sha=sha256(JCS(lane_family))` is bound into every committee assignment, certificate and ATTEST_ENVELOPE (§3–4); family subsets are derived by lookup, never stored. The policy lint requires exact membership and checker digests at genesis; amendments validate the authorized §6 policy chain and disjointness, completeness, opposite-family keyholder eligibility, one emergency key per family and at least two enrolled attestation helpers per family, each a distinct §6-qualified checker under its own custody principal and protected invocation path (§4), enumerating the surviving cross-family pairs per helper loss; any unauthorized swap or omission, duplication or mislabel fails before any committee assignment (Scenarios 19, 60).

Widening eligibility requires §6 and, where a bench mandates a high-risk PR gate, that gate too before taking effect.

## 1. Architecture and durable publication

**Claims use CAS refs.** Oracle activation requires reftable (`extensions.refStorage=reftable`), qualified with all shared-ODB tooling and crash-atomic multi-ref publication in Stage S. `<S>` is lowercase hexadecimal encoding of immutable subject-ID UTF-8 bytes, without casefolding. `refs/oracle/claim/<S>` points to `{subject, owner, lease_gen, claimed_at, job_id, pid, creation_time, paths_digest}`; `refs/oracle/lease/<S>` stores `{lease_gen, lease_until}` and renewal changes only this ref. claimed_at and lease_until carry `clock_domain=oracle`; OS creation_time carries `clock_domain=real`. `update-ref --stdin` transactions (`start`, `update`/`verify` per ref with expected OID, `prepare`, `commit`) use the zero OID for absent refs. A lost dependency CAS backs off `50·2^i ms (clock_domain=real)`, `i=0…7`, then defers that subject. No claim/vote operation takes `.git/index.lock` (Scenarios 1, 14, 49).

**Framed journals.** Each lane has one authorized append helper at `<git-common-dir>/oracle/journal/<lane>.ndjson`, serialized by a lane mutex derived from §7 repository identity plus lane. A frame is a JSON line `{seq, prev_frame_sha, payload_len, payload, checksum}` of at most 3500 UTF-8 bytes; journal heads are commits parenting predecessors, with trees retaining frame and oversized-evidence blobs; receipt commits parent consumed journal heads; the checksum covers the canonical frame, signatures the payload envelope. Durability acknowledgment requires append, `FlushFileBuffers`, durable Git object storage with `core.fsync=loose-object,pack,reference` and `core.fsyncMethod=fsync`, verified by every Oracle writer before acknowledgment, and CAS advancement of `refs/oracle/journal-head/<lane>` to a commit containing metadata `{seq, frame_sha, blob_oid, previous_head, timing}`; `timing` `{frame_sha, seq, boot_id, qpc_counter, qpc_frequency, real_time, mapping_digest}`, signed with the append helper's role-restricted key (§7), never the lane vote key, immediately after `FlushFileBuffers` returns, is the frame's reducer-independent t_recv. Recovery validates sequence, chain, length and checksum through the acknowledged head, ignores unacknowledged tails and rotates to a new segment before further writes; a crash after head publication but before client acknowledgment permits an idempotent retry; flush failures withhold acknowledgment (Scenarios S, 16, 35, 61).

**Receipt and reducer.** One `oracle-reduce.py` instance per shared Git object database (§7) ticks every `200 ms (clock_domain=real)`. It pins complete head prefixes to an immutable receipt commit under `refs/oracle/receipts`, assigning `(receipt_seq, lane, frame_seq)` once and preserving the helper-issued `timing` as `t_recv (clock_domain=real)` with its paired oracle timestamp; replay retains published receipts through the receipt-head parent chain; live receipt OIDs are never pruned. The reducer reads only committed receipt inputs, checks signatures and fences, applies idempotency, and publishes at most `N_batch=100` rows per publication period `P_pub=max(P_floor, c_p99)`, derived, never literal, from measured `clock_domain=real` durations (Scenario 68): `P_floor=max(tick, max_r(d_r/k_r))`, d_r resource r's service per batch (transport and retries included), k_r its parallel capacity, c the serialized-commit duration and c_p99 its measured p99; `refs/oracle/state` republishes no faster.

**Atomic publication.** A private index builds the state tree (cursors, `applied.csv`, `verdicts.csv`, subject state, notices). One git transaction verifies every relevant claim OID, the reducer lock OID and any other mutable dependency, and CAS-updates `refs/oracle/state`; expiry decisions also verify lease OIDs. Only changed dependent subjects are recomputed; after six dependency losses they are split out so independent subjects publish. A state-ref CAS loss means competing publication: exit 3, release the mutex (Scenarios 28, 49, 50).

The reducer never checks out, resets or writes shared worktree files; every Oracle Git invocation sets `GIT_NO_REPLACE_OBJECTS=1`; readers use `git --no-replace-objects show refs/oracle/state:<path>`; caches are regenerable. The §5 mailbox writer privately CAS-updates non-authoritative `refs/oracle/mirror` with `verdicts.csv` every `1 h (clock_domain=real)`; eight failed attempts yield MIRROR_CONTENDED.

**Cursor invariant.** Cursors and applied effects share one state publication: `committed_cursor(lane) ≤ committed_applied_high_water(lane)`.

**Observation and cadence.** The supervision cadence has four drivers (reducer `200 ms` tick, sidecars and §4 floor sweeps `30 s`, floor wakes `900 s`, all `clock_domain=real`): the reducer loop runs dispatch, DARK detection, outbox sequencing and helper/adopter invocation; every live lease sidecar (§2) runs `oracle-reduce.py --ensure` from outside the reducer's Job Object; floor wakes run `--ensure`. Journal movement, floor wake, role completion, dispatch failure and outstanding assignment age are recorded separately (Scenario 34).

**Reducer capacity.** At most two bounded workers may prevalidate immutable inputs (parsing, signatures, digests) ahead of the single publisher, which revalidates every dependency itself. Depth-1 (serial) prediction `μ1=min(μ_receipt, μ_validation, N_batch/max(P_pub, t_build+c))` rows/s, t_build the measured batch build time, μ_receipt the measured receipt-commit rate and μ_validation the measured prevalidation throughput (Scenario 68), at no more than `1/P_pub` state commits/s. Demand at implementer count `N_exec ∈ {5, 9, 15}` (§5 `executors`; V, A and helper counts are reported separately) is measured: `D_N = λ_N·τ_N + b_N` rows/s (arrivals × transitions per arrival + background renewals, receipts and retries) (Scenario 68); D_N and μ feed the §9 resource gate.

**Pipelined publication (Phase 2 lever, `provisional`).** When measured reducer saturation binds (§9), a POLICY amendment may qualify depth-two pipelining (depth ≤ 2, receipt order kept): the reducer builds batch n+1 in private memory against n's proposed state, pinning n's exact state OID and the expected pre-/post-n vector of every dependency it consumes (claim, gate and `pending/*/<S>` OIDs, §4), rereading it at each build stage and before handoff (an unexpected change discards the build and its descendants) and re-verifying every dependency against the committed n OID in its publication transaction; speculative work has no external effect. A crash at the handoff leaves n committed or absent and n+1 rebuilt from committed state; rollback disables depth two and rebuilds unpublished work serially, never reversing history. Prediction `μ2=min(μ_receipt, μ_validation, N_batch/max(P_pub, t_build, c))`; only `μ2−μ1` at identical P_pub, workload and N_batch is credited. Gain `CI95.upper ≤ 0`, growing downstream queues, publication p99 above `10 s (clock_domain=real)` or any replay or safety divergence leaves pipelining disabled. Scenario 20 measures capacity μ at offered `demand_rows_per_s = target_multiple × baseline_items_per_h × transitions_per_item / 3600` (§5 M4).

## 2. Claims, leases, artifact binding and mutation fencing

**Admission and ownership.** The reducer admits and assigns a subject (§3, §5) and publishes a signed PERMIT bound to policy_sha, lane_family_sha, pre-candidate scope and the subject's path allocation. PERMIT, CERTIFICATE and ATTEST_ENVELOPE objects are immutable at `refs/oracle/objects/<S>/<kind>/<state_object_digest>`; immutable global objects (oracle_mapping, bridges, measurement windows, latch episode-state objects, outbox entries, helper requests and results) at `refs/oracle/global/<kind>/<id>`. The mutable refs under `refs/oracle/` are exactly `claim/<S>`, `lease/<S>`, `authority/<S>`, `path-index`, `path-allocation/<S>`, `reducer/lock`, `journal-head/<lane>`, `adopted/<S>`, `state`, `receipts`, `mailbox`, `mirror`, `global/latch/<p>`, `global/lane/<lane>`, `global/outbox-head`, `global/outbox-relayed`, `global/measure-checkpoint/<id>`, `gate/<S>`, `pending/<lane>/<S>` and `pending/reducer/<S>`, advanced only by expected-OID CAS (T/O claim and lease; G journal-head, lane pending and, for PENDING_TRANSFER, `gate/<S>`; mailbox, mirror and the relay cursor by the §5 mailbox writer; L otherwise), never called immutable; each transaction's generated `mutable_reads[]` manifest lists exactly the refs it verifies (correctness dependencies only) (Scenario 42a). `refs/oracle/authority/<S>` names the subject's current permit, certificate and attest_envelope digests and changes in the transaction creating a new object. A claim transaction verifies exactly its PERMIT OID, `authority/<S>`, `path-allocation/<S>` and its own claim/lease OIDs, binds `paths_digest` to the allocation's state_object_digest and creates/updates claim and lease refs, never verifying `refs/oracle/state` (Scenario 49). `lease_gen` increments exactly on claim, reclaim or FORCE_RELEASE, never on renewal; reclaim consumes the retired generation and writes the next. `verdict_ver` changes only on RECHECK or successor issuance (§3). committee_epoch (semantic seats) and attest_epoch (deterministic seats), both per subject, account_epoch (per provider, §5) and policy_epoch (global) are separately scoped counters (Scenarios 1, 24–26, 67).

**Immutable candidate.** COMPLETE, every semantic proof, certificate, ATTEST and adoption binds `C = {subject, phase, verdict_ver, implementer, lease_gen, base_commit_oid, candidate_commit_oid, candidate_tree_oid, patch_sha256, acceptance_spec_sha, dependency_certificate_digests, policy_sha}`; `candidate_digest=sha256(JCS(C))`. A bench profile requiring PR, attempt or producer provenance binds it in one compact profile receipt signed at COMPLETE, keyed by candidate_digest, not in C; a candidate produced by more than one implementer lane records every actual producer in that receipt. COMPLETE verifies candidate object/tree/patch consistency against the recorded base and rejects any changed path, either side of a rename included, outside `path-allocation/<S>`; review reads these immutable objects, never worktree bytes; acceptance requiring derived visual or audio evidence supplies it to semantic reviewers as immutable candidate-bound objects through the §4 acceptance receipts, never as C fields. Any artifact, base, dependency or acceptance change creates a successor with fresh review. An unchanged artifact retains its historical lease_gen after owner retirement; later proofs bind C without acquiring owner privileges (Scenario 47).

**Lease sidecar.** The ignition wrapper starts `oracle-lease-sidecar.py --subject S --pid P --job J` with TTL `1800 s (clock_domain=oracle)` and RENEW `600 s (clock_domain=oracle)`. Renewal requires matching lane, lease_gen, PID creation time and Job Object membership, verifies the claim OID and CASes the lease ref; changed ownership or lease_gen terminates the sidecar.

**Hard horizon.** H defaults to `180 min (clock_domain=oracle)` until §9 qualifies a configuration-specific tail; then `H=clamp(1.25×p99_oracle,180 min,360 min) (clock_domain=oracle)`, p99_oracle mapped through the production SCALE=1 mapping. The sidecar refuses renewal at H. Reclaim eligibility is exactly:

```
lease_until < oracle_now - grace OR oracle_now >= claimed_at + H
grace = 60 s (clock_domain=oracle)
```

**Path exclusion and stop barrier.** All executors are non-breakaway Job Objects with kill-on-close. The reducer alone allocates canonical Windows path sets (aliases/reparse points resolved, casefolded, ancestors included for directory writes; unknown scope and branch/index mutations acquire the whole checkout): one transaction updates the reducer-private overlap index `refs/oracle/path-index` and `refs/oracle/path-allocation/<S>`; allocations cannot overlap. With staggered holders, whole-checkout requests waiting `5 min (clock_domain=real)` stop new path grants until serviced; existing holders finish or reach H under the stop barrier. Before reassignment, recovery records `STOPPING`, terminates the whole prior Job Object including its sidecar, confirms no member remains, records `{job_id, creation_time, exited_pids, termination_receipt}`, then atomically retires the claim and releases paths; no termination confirmation ⇒ `BLOCKED-TERMINATION`, paths retained, no replacement writer.

At horizon the reducer issues FORCE_RELEASE with pre-CAS lease_gen after stopping the old job; orphan expiry (LEASE_EXPIRED, emitted once when the first disjunct holds) and reclaim use the same stop barrier. Eligibility occurs by `1860 s (clock_domain=oracle)` after orphaning, or H for a live hang, plus at most one reducer tick; stop/reassign target is `30 s (clock_domain=real)` after detection, conditional on termination succeeding (Scenario 48).

**Event registry.** This closed table is the only authority on event kinds. Fence classes: **O** actor=owner with current lease_gen at publication (a stale row receives the `applied.csv` disposition STALE_LEASE); **T** authorized transition carrying pre/post OIDs and pre-CAS lease_gen, state effect and ref mutation atomic; **R** verification-only recovery of a completed ref transition; **E-seat** current committee_epoch/attest_epoch, assignment_digest and seat eligibility (or a current-epoch REAFFIRM of a prior-epoch proof, §3); **E-elig** current committee_epoch and keyholder eligibility only; **A-cfg** actor is selected by current adopt_mode under the current policy_epoch; service additionally requires recorded custody ratification; **C** current certificate_digest; **S** subject-state CAS; **P** authorization under the prior policy; **L** reducer lock OID verified in the publishing transaction; **I** helper-result ingress (§4): the assigned principal's signature, nonce equal to its HELPER_REQUEST's, current epochs, first result per request_id; **G** a lane's append helper under its lane mutex advancing its journal head or performing BLOCKING_PUBLISH or PENDING_TRANSFER (§4), verifying expected OIDs, generation and eligibility, touching no peer entry or foreign gate. Idem forms are in §3. State and gate objects are published by CAS on their own refs, not journal frames; every state object has `state_object_digest=sha256(JCS(object without signatures))`; `certificate_digest` is the CERTIFICATE's state_object_digest. An unknown kind fails validation.

## 3. Semantic verification and committee authority

**Joint allocation.** At admission and each reassignment, enumerate every fully eligible `(V.a,V.b,A.1,A.2)` tuple from §0 policy. V.a is an available keyholder in the family opposite the implementer; V.b an available second-vote-eligible lane in the family opposite V.a, distinct from the implementer; neither is a producer recorded in the §2 profile receipt (lanes excluded, never families). A.1 and A.2 are distinct registered helpers (§0, §4), one enrolled CODEX (A.1) and one CLAUDE, with different implementations and custody principals, excluding ATTEST_SUSPECT helpers, each with a live floor verified able to start it.

Load is computed from the pinned `prior_state_oid`: for lane l under tuple T, `L_l(T)=(Q_l+Σ_{s: T_s=l} d_s)/c_l`, Q_l the lane's remaining reserved service microseconds, d_s the new role's service-demand microseconds (fulfilled proofs and helper seats contribute 0), c_l its positive concurrent slots; missing estimates use the provisional `d=1,000,000 µs, c=1`; reservations keep their originating estimates. Select the lexicographic minimum of `(max_l L_l, Σ_l L_l, SHA256(JCS([subject,committee_epoch,attest_epoch,policy_sha,prior_state_oid,T])), T)`, T compared as ascending UTF-8 lane IDs in fixed seat order. Persist eligibility, policy_sha, lane_family_sha, candidate_digest (once bound), deadlines, load inputs and checker digests in `committee/<S>.json`; `assignment_digest=sha256(JCS(committee/<S>.json))`.

No feasible tuple ⇒ durable WAIT-COMMITTEE; absent required family ⇒ WAIT-FAMILY. Both retry at `30/60/120/240 s`, then every `240 s`, until `15 min` after the first WAIT record (all `clock_domain=real, provisional`), when the subject records BLOCKED-CAPACITY and thereafter wakes only on its recorded cause's evidence (role completion or reservation release freeing required capacity, successful ROLE_CAPACITY_PROBE, LATCH_CLEARED, ROTATION_COMPLETE or policy amendment) (Scenarios 40a, 40b, 53).

**Deadline misses, clock misses and lineage cap.** Per lane the reducer owns one CAS state object `refs/oracle/global/lane/<lane>` (LANE_HEALTH) = `{miss_count, clock_miss_count, shadow_ok_count, suspect, clock_suspect, recovery_episodes}`, verified (fence L) and advanced in the publishing transaction with effects and cursors; misses count exactly once under parallel reassignment and replay (idem keys: §2). An attributable missed deadline (start `15 min (clock_domain=real)` or execution H) increments `miss_count`; at `N_miss=2 (provisional)` the reducer records V_SUSPECT, excluding that lane from outstanding V assignments, completed valid proofs surviving. A miss attributable to clock incomparability (below) is CLOCK_MISS, incrementing `clock_miss_count` once per distinct authenticated frame, durably across restart and reseating, feeding neither V_SUSPECT nor rehabilitation; at `C_max=3 (provisional)` consecutive misses the reducer records CLOCK_SUSPECT, excluding the lane from new seating with `miss_count` and `shadow_ok_count` untouched; one fresh bridged comparable frame clears only this cause and zeroes the count. A latch-suspended deadline (§5) accrues no miss; probes and wakes never clear one. Rehabilitation requires three non-gating V_SHADOW_REQUESTs answered by timely V_SHADOW_RESPONSE within both deadlines (`shadow_ok_count`), then V_REHABILITATED; an attributable miss resets the count; a CLOCK_UNCERTAIN shadow neither advances nor resets it. Per subject lineage (across verdict_ver successors) automatic V_REASSIGNs and HOLD successors (HOLD_ADJUDICATED or HOLD_EXPIRED) are counted together; at `K_lineage=3 (provisional)` BLOCKED-CAPACITY is recorded, an exhausted HOLD retaining its unresolved state durably instead of enqueuing a successor. Counters survive restarts, epochs and successors; only newly qualified capacity (a V_REHABILITATED lane, a §6 amendment, LATCH_CLEARED or ROTATION_COMPLETE for the missing family) opens one V_RECOVERY_EPISODE with `K_lineage` further reassignments or successors (Scenarios 52, 67).

**Availability.** Semantic DARK means a failed authenticated provider probe, a family latch, or no successful signed role completion/probe for `30 min (clock_domain=real)`; wakes and unrelated appends never reset it; a successful ROLE_CAPACITY_PROBE restores it when no latch episode is OPEN for that provider (§5): the reducer requests one at most once per lane, role and aligned `240 s (clock_domain=real)` window while the lane is DARK or a WAIT names its family; the §5 adapter answers through HELPER_RESULT (§4) with one authenticated minimal inference call, charged once to M6; an inference-free probe proves no semantic capacity. Only outstanding semantic assignments are replaced; missing either deadline above reassigns with committee_epoch+1 through V_REASSIGN. While an outstanding semantic seat is parked on a latch (§5), its deadlines and the HOLD TTLs below suspend and resume from their remaining balance at LATCH_CLEARED or ROTATION_COMPLETE (Scenarios 5, 18, 52).

**Dispatch and carry-over.** V_REQUEST dispatches both V seats together at COMPLETE. After reassignment, resumption (§5) or reducer recovery, only obligations still missing for the unchanged C (an unfulfilled V seat, a pending ATTEST, an ATTEST_ENVELOPE absent from a sealed subject's authority ref, an undelivered adoption, an unrelayed outbox entry, a retained voter's missing current-epoch REAFFIRM requested through V_REQUEST) are re-dispatched. Prior-epoch semantic proofs count only for the same C, pinned policy and a voter still in current V. `REAFFIRM {proof_id,candidate_digest,committee_epoch,assignment_digest}`, proof_id being the retained V proof's state_object_digest, verifies the retained proof and current seat, deduplicates independently, and supplies epoch freshness; a demoted lane's reaffirmation is inert (Scenario 51).

**Pair rule and the one terminal transition.** Collection starts at COMPLETE. Once both V seats have valid votes or an effective REJECT arrives, open a `30 s (clock_domain=oracle)` convergence window, persisting deadline and mapping; recovery restarts it only through the single RECOVERY_RETRY below. At close the reducer applies the precedence below; only precedence 5 *stages* a proposed decision, READY or REJECTED, by publishing the immutable certificate object (§2) binding C, both V proofs, committee_epoch, policy_sha and lane_family_sha, and emitting ATTEST_REQUEST to both A seats (§4). The sole terminal transition is SEAL, a CAS from a nonterminal state at most once per `(subject,phase,verdict_ver)`, requiring: (i) agreement on the exact C and outcome from both assigned V seats, a graded-verdict bench profile first reducing each vote to ACCEPT or REJECT through its pinned authorized predicate; (ii) at least one current-committee_epoch action; (iii) two eligible, independently implemented, cross-family A checks agreeing on the certificate's digests; (iv) no effective keyholder REJECT against a READY proposal. A changed committee may start a new window only before sealing. Precedence:

1. CONFLICT ⇒ HOLD. Invalid signer/actor binding or two different authenticated reducer outputs for one decision is a conflict; a lane equivocating on verdict_value for the same C is SELF_CONFLICT and both its votes are discarded.
2. Split pair ⇒ HOLD for non-party keyholder ADJUDICATE, target `5 min (clock_domain=oracle)` (Opus only if eligible and non-party; with no non-party, retain HOLD). ADJUDICATE proposes the successor's outcome and reason, supplies no ballot and never seals: the reducer atomically (S+L) records HOLD_ADJUDICATED and enqueues exactly one fresh-review successor at verdict_ver+1, committee_epoch+1, seeded with the reason. The one collection TTL, `2 h (clock_domain=oracle)` from COMPLETE, applies to every HOLD; at expiry HOLD_EXPIRED likewise enqueues exactly one successor, never a synthesized REJECTED; exactly one of the two fires per `(subject,phase,verdict_ver)`, within the lineage cap above.
3. Lone REJECT, other seat silent ⇒ HOLD until the pair completes or the collection TTL expires.
4. A current-epoch eligible keyholder outside V rejecting ⇒ HOLD, REJECT_OUT_OF_PAIR, pending ADJUDICATE as in 2, never sealing; its ACCEPT is RECORDED_NO_EFFECT; a prior-epoch outside-seat REJECT is inert.
5. Both seats agree ⇒ stage READY or REJECTED; otherwise HOLD-VERIFY until the collection TTL expires. One RECOVERY_RETRY (fence S+L) is permitted when the reducer restarts with an unsealed decision for unchanged C: it reopens the `30 s (clock_domain=oracle)` window once, then this precedence applies.

**Idempotency.** Keys hash canonical tuples under the subject's pinned policy_epoch:

```
event:   [policy_epoch,subject,phase,lease_gen,kind,actor,sha256(payload)]
vote:    [policy_epoch,candidate_digest,"vote",actor,canon(verdict_value)]
reaffirm:[policy_epoch,candidate_digest,"REAFFIRM",actor,proof_id,committee_epoch]
attest:  [policy_epoch,candidate_digest,certificate_digest,committee_epoch,attest_epoch,seat,batch_id,actor,checker_digest,input_digest,output_digest,result]
policy:  [policy_epoch,kind,subject_sha,actor]   # subject_sha: new policy sha, key_id or checker_digest
adopt:   [policy_epoch,candidate_digest,certificate_digest,attest_epoch,"ADOPT_REQUEST",actor]
rotation:[provider,account_epoch,latch_id,kind]
gate:    [policy_epoch,subject,lane,set_digest]   # set_digest: JCS of the transferred {seq,frame_digest} set
state-CAS: state_object_digest; publication is CAS on its ref
```

A semantic retry receives the `applied.csv` disposition DUPLICATE_OK (counted once, no effect). `applied.csv={idem,t_applied,proof_id,source_offset,disposition}` commits with effects; buffered submissions retain idem and replay until acknowledged (Scenarios 6, 9, 16, 39).

**Seal, lateness and challenges.** A sealed certificate fixes its semantic committee (helper replacement: §4). Receipt order (§1) sequences processing; the append-helper-signed t_recv interval, never lane self-time or reducer resume time, determines timeliness through the §8 comparability predicate: timely credit requires the t_recv interval's upper bound ≤ the persisted deadline's lower bound; `late=1` requires its lower bound > the deadline's upper bound; anything else is CLOCK_UNCERTAIN, persisted per frame. If unresolved after `120 s (clock_domain=real)`, an ACCEPT or REAFFIRM earns no positive credit and only `clock_miss_count` increments, while a valid REJECT remains protective in receipt order. Every deadline, expiry or reassignment decision first drains the acknowledged journal heads of the subject's assigned lanes (Scenario 11). A helper real_time more than `SKEW=120 s (clock_domain=real)` from receipt flags CLOCK_SKEW: audit-only. A late valid keyholder REJECT atomically creates an unresolved challenge and advances active_verdict_ver through RECHECK before any later adoption; post-adoption challenges produce successors and remediation notices, delivered history intact (Scenarios 17, 55).

## 4. Replay, deterministic attestation, quarantine and adoption

**Replay closure.** Each `inputs/<batch_id>.json` pins every decision input: prior_state_oid, receipt commit/ordering and journal byte ranges, relevant mutable-ref OIDs and transitions, prior applied-tail hash, candidate tuples, dependency graph, committee assignments and load inputs, policy content, migration records, key validity/revocation evidence, checker/reducer code digests, oracle_mapping and bridge objects, persisted deadlines and provider/probe snapshots. No replay reads mutable policy, current keys, wall time, live refs or provider state. Canonicalization is RFC 8785 JCS, UTF-8, integers only; input_digest hashes the closure; per-subject output_digest covers decision, reasons, C and dependency results, excluding digest/signature fields. The certificate binds these digests, C, V proofs/reaffirmations, committee and pinned policy; `--verify --at <sha>` replays read-only from this closure (Scenarios 43, 54).

**Independent checkers.** Register four independently implemented, §6-qualified transition checkers (§0: two per family) with immutable executable/test-suite digests; they may share canonical parsing and cryptography, not the reducer's transition implementation. Each validates authority, arithmetic, dependencies, fencing and output against pinned prior state; disagreement is arbitrated without inference (below; Scenario 60).

**Attestation helpers.** An A seat is a logical helper `helper_id=(checker_digest, custody_principal)` enrolled in §0 policy with a family. Custody principals' (§7) envelopes carry only ATTEST, MISMATCH and SHADOW_ATTEST over the checker's own output, never implementer or V custody. **Invocation contract.** Each helper is a fixed-action Windows scheduled task under its dedicated principal, registered only by an owner-installed change verified against its §6 enrollment before activation; lanes and floors never register, enable or edit it, floors holding task-start permission only, never task-edit, binary-write or key access. A floor CAS-creates the immutable HELPER_REQUEST ref `refs/oracle/global/helper-request/<request_id>` = `{operation, subject, certificate_digest, input_digest (closure), assignment_digest, attest_epoch, policy_sha, idem, attempt, nonce}`, `request_id=sha256(JCS(request without nonce))`, then starts the task. The helper validates the request against pinned inputs and CAS-creates (zero OID expected) the immutable HELPER_RESULT `refs/oracle/global/helper-result/<request_id>` = `{request_digest, nonce, operation, candidate_digest, checker_digest, result_digest, payload, assignment_digest, committee_epoch, attest_epoch, signature}` under principal-restricted mutation admission (fence I, §2). The reducer polls outstanding request_ids each tick, verifies eligibility, seat and every binding, and commits each result's disposition (`applied.csv`: ACK, STALE, INVALID) atomically with its effects; no result by `T_helper=120 s (clock_domain=real)` after request publication records HELPER_TIMEOUT once and re-sweeps at attempt+1 (a fresh request_id) after backoff `min(T_helper·2^attempt, 960 s) (clock_domain=real, provisional)`, never erasing an admitted MISMATCH; at most `N_helper=3 (provisional)` attempts per obligation and two outstanding requests per helper (provisional); exhaustion records durable BLOCKED-CAPACITY for that subject, resumed only by a later successful HELPER_CAPABILITY_PROBE for that helper or its replacement, unrelated subjects continuing. Eligibility (§3) requires a signed HELPER_CAPABILITY_PROBE within `30 min (clock_domain=real)` showing a live floor can start the helper. Replacing an unavailable principal or checker increments only attest_epoch and reissues the ATTEST_ENVELOPE (§2), keeping C, verdict_ver, the sealed certificate and every V proof; both current seats recheck; a superseded-epoch or superseded-seat ATTEST is inert; adoption verifies the current assignment atomically (Scenarios 57, 65, 69).

**Inference-free scheduling.** At staging (§3) the reducer starts both helper tasks immediately (§1 cadence); every live floor in `helper_floors` sweeps helper/adopter requests every `30 s (clock_domain=real)`, separate from reducer-recovery wakes; a bench profile prohibiting Tier 3 cadence wakes may narrow `helper_floors` while every helper retains a floor able to start it (§3).

**SEAL transaction and envelope.** Once cross-family attestations satisfy SEAL, one transaction (S+C+E-seat+L) verifies the certificate already published at staging (§3) and publishes the sealed subject state, the immutable ATTEST_ENVELOPE ref, `refs/oracle/authority/<S>` adding the envelope digest, and the durable ADOPT_DISPATCH row. The envelope is a pure function of sealed inputs `{certificate_digest, committee_epoch, attest_epoch, assignment_digest, authorizing pair (helper_ids, checker and proof digests), lane_family_sha}` from `committee/<S>.json` and references no enclosing commit; SEAL also verifies an empty `pending/reducer/<S>`. Recovery re-derives it: a sealed subject whose authority ref lacks an envelope digest receives one by state-CAS under the current authority OID (idempotent on digest) and is re-dispatched (Scenario 57).

Dispatch target `5 s (clock_domain=real)` per hop, `T_helper` per helper or adopter execution, READY-to-adoption p95 target `15 min (clock_domain=real)`; at `35 min (clock_domain=real)` without adoption publish ADOPT-DEFERRED (Scenarios 32, 33, 57).

**Authorization.** Default `live-sol` runs oracle-adopt.py through Sol's existing native floor runner and signing custody, signing ADOPT_REQUEST only after its own independent replay agrees and the acceptance_spec_sha-required runs are independently executed or authenticated against receipts binding C.candidate_commit_oid, commands, toolchain digests, configuration, environment (including TEMP/TMP), expected/observed test identities, result digests and exit codes; missing tests or disallowed failures/skips invalidate acceptance; receipt digests bind ADOPT_REQUEST and its replay closure. Optional `service` uses a registered `sol-adopt` least-privilege identity whose ACL excludes lane runners, casts zero votes.

**Quarantine closure.** A valid MISMATCH immediately fences the smallest transitive dependency closure that consumed the suspect input/output, by explicit per-subject provenance (co-publication is not a dependency; corrupt shared evidence or insufficient provenance includes all consumers); the whole first-red batch is preserved and QUARANTINE_OPEN appended per affected subject `{first_red_sha,root_evidence,closure,opened_at,stage}`; unaffected subjects continue.

Both A checkers rerun against a last validated prior state and retained inputs; two authorized, independently implemented, cross-family agreeing valid checks determine the outcome. Agreement with the proposed output clears a false alarm through UNQUARANTINE; agreement on a corrected output records QUARANTINE_CORRECTED and requires a successor verdict_ver with fresh certification, never mutating bad rows. Disagreement dispatches, by `15 min (clock_domain=real)`, arbitration seat A.3: the lowest `sha256(JCS([subject, verdict_ver, "A3", helper_id]))` among live, non-ATTEST_SUSPECT enrolled helpers (never lanes) not already seated; a match between A.3 and the initial helper of the opposite family is the authorizing pair; a match only within A.3's family dispatches A.4 by the same rule with label "A4" and family opposite A.3. Each arbitration seating atomically increments attest_epoch and republishes assignment_digest in `committee/<S>.json`, so every seat's ATTEST/MISMATCH carries the C+E-seat fence and retained seats recheck under fresh epoch-bound requests; only a unique cross-family agreed output resolves, its pair (lowest seat labels), their helper_ids, checker/proof digests, assignment_digest and attest_epoch bound into UNQUARANTINE, QUARANTINE_CORRECTED and any SEAL/envelope; conflicting agreements stay quarantined under the original deadlines. At `30 min (clock_domain=real)` unresolved, or with no such live helper, the closure becomes durable QUARANTINE-BLOCKED, retried on checker recovery (Scenarios 31, 37, 60).

A helper is ATTEST_SUSPECT only after independent evidence validates its fault; it then answers non-gating SHADOW_ATTEST_REQUESTs with SHADOW_ATTEST records. ATTEST_REHABILITATED requires three consecutive successful distinct injected-fault challenges (artifact substitution, stale authority, wrong transition) plus one clean historical replay, any failure resetting the count; code remediation changes checker_digest and requires requalification (§6).

**One readiness predicate.** Every phase/dependency/adoption gate calls:

```
ready_effective(row,current) := row.state == READY
 AND row.verdict_ver == current.active_verdict_ver
 AND row.candidate_digest == current.candidate_digest
 AND row.committee_epoch == current.committee_epoch
 AND current.attest_envelope.attest_epoch == current.attest_epoch
 AND current.attest_envelope.lane_family_sha == current.subject_policy.lane_family_sha
 AND row.policy_sha == current.subject_policy.sha
 AND NOT current.unresolved_challenge AND NOT current.quarantined
 AND all_dependency_certificates_current_and_valid(row)
```

`current.attest_envelope` is the envelope selected by `refs/oracle/authority/<S>`; `all_dependency_certificates_current_and_valid(row)` holds iff every digest in `C.dependency_certificate_digests` names the certificate currently selected by its own subject's `refs/oracle/authority/<D>` and that subject satisfies `ready_effective` recursively.

**Adoption linearization.** The adopter submits a signed request binding C, certificate_digest, the ATTEST_ENVELOPE, both valid attestations and its own independently computed output. Each subject has a reducer-owned gate `refs/oracle/gate/<S>` = `{generation, status: OPEN|CLOSED, frontier[lane]: {published: {seq, frame_digest}, drained: {seq, frame_digest}}}`. A lane's potentially blocking publication against S (keyholder REJECT, challenge, dependency successor) is acknowledged only after BLOCKING_PUBLISH (fence G, §2): one transaction advances its journal head and unions `{seq, frame_digest}` into its own `refs/oracle/pending/<lane>/<S>` per affected subject, touching no gate. PENDING_TRANSFER (fence G, under the lane mutex) then moves one pending set into one OPEN gate: one CAS transaction advances only `frontier[lane].published` (deduplicated by frame digest, peer entries preserved) and empties that pending ref; a lost CAS preserves the entries and releases the mutex, six losses deferring that gate alone for round-robin retry; a CLOSED gate keeps entries pending until reopening; acknowledged pending entries are not drained until transferred. An admitted MISMATCH is unioned as `{request_id, result_digest}` into the reducer-owned `refs/oracle/pending/reducer/<S>` (fence L), from which FRONTIER_ADVANCE (S+L, §2) moves it into each affected OPEN gate under the same rule; a mismatch citing an obsolete request triggers a current-bound recheck before reopening. Adoption CASes the gate CLOSED (GATE_CLOSE), capturing every lane's published position; the reducer drains exactly those positions, recording each `drained`, then in one ref transaction verifies the closed-gate OID, reducer lock, the exact certificate, attest_envelope and `refs/oracle/authority/<S>` it consumes (never `refs/oracle/state`), dependencies, readiness, an empty pending ref for every lane in the pinned challenger membership (current eligible keyholders and assigned V lanes) and for `reducer`, and unchanged gate OIDs across the pinned dependency closure; it then publishes the authenticated adoption record, `refs/oracle/adopted/<S>` at the exact candidate commit, and the gate reopened at generation+1 with every captured entry preserved. Closure targets `2 s (clock_domain=real, provisional)`; on overrun the gate is durably reopened with ADOPT-DEFERRED, no acknowledged evidence dropped. Recovery reads `refs/oracle/adopted/<S>` before any timeout handling: a valid match is delivered permanently and recovery (fence R) only verifies that its gate is open; absence permits retry through ADOPT-DEFERRED; inconsistency records ADOPT-INCONSISTENT and blocks the subject; a challenge acknowledged after the winning transaction is post-adoption. Consumers validate adopter signature, cross-family proofs and exact candidate before using an adopted ref (Scenarios 50, 55).

Adoption records are keyed by `(subject,phase,verdict_ver,adopter)`. Insufficient valid attestors, or missing independent custody in either family, yields ADOPT-DEFERRED, never identity substitution, retried each sweep, with one ADOPT_BACKLOG after `24 h (clock_domain=real)`.

## 5. Capacity evidence, advisory budgets and rotation

**Owner directive (2026-09-13), binding throughout.** Budget_mode (§0) defaults to unrestricted. W, budgets, R_p and u_r are advisory; UNKNOWN, stale or exhausted estimates never stop admission, probes or required work. Safety, custody and measured-scale qualification remain binding.

**Provider evidence.** For each provider p ∈ {codex, claude} the quota adapter (`provisional`, 1b-build §10) extends `coordination/tools/check-cli-auth.py --json` with `providers[p].{account_id, limit_lower, limit_upper, remaining_lower, reset_at, observed_at, receipt, unit}`: bounds are nonnegative integers in `unit`; unknown `limit_upper`, `reset_at`, `account_id` are null, an unknown lower bound zero; timestamps UTC; `receipt` is the PROBE_RECEIPT below; extraction reads only authenticated CLI output through a versioned per-provider, per-CLI-version mapping `{source JSON pointer, destination field, unit, transformation, fixture}` and validates provider/account binding. Until the adapter ships, or when extraction is unsupported, malformed or contradictory, `providers[p]` is UNKNOWN; a successful inference call proves no allowance. `budget_p=remaining_lower`; `W_p=limit_upper`, nullable, never divided by. Observed consumption is a lower bound, never a balance. With no episode OPEN for p, one routine refresh probe per aligned `240 s (clock_domain=real)` window (idem `[provider, account_epoch, "REFRESH", window_start]`, `window_start=floor(t_request/240)·240`) refreshes evidence, STALE after `300 s (clock_domain=real)`; it never clears or advances an episode, and an authenticated refusal inside it opens one.

**Probe contract.** The authenticated adapter alone executes probes, each scheduled by the reducer and deduplicated, before any counter moves, by `(provider, account_epoch, latch_id, request_id)` inside an episode or the refresh key above outside one. While an episode is OPEN, recovery probes follow delays `60, 120, 240, …, 3600 s (clock_domain=real)`, doubling to the cap; changed-account evidence triggers an immediate probe. Every probe returns a signed PROBE_RECEIPT `{adapter_digest, configuration_digest, provider, account_epoch, nonce, request_id, t_request, t_response, redacted_response_digest, extracted: {limit_lower, limit_upper, remaining_lower, unit, reset_at}, outcome, usage, success_count, signature}`, `success_count` the reducer-validated episode value after this receipt (null outside an episode); a replayed, stale-episode or malformed receipt clears nothing; every probe call's actual usage is charged once in M6 and advisory R_p (Scenarios 30, 70, 71).

**Units.** Per provider: `request` → one per provider request; `token` → the provider's own metered input/output quantity; `credit` → Σ authenticated rate coefficients × metered quantities. Every `cost_bound(subject,role,p)` is in the `unit` of `providers[p]`; a missing coefficient or incomparable dimension yields UNKNOWN, never an assumed exchange rate. The conversion is the signed M7 record `{provider, account_id, model, effort, role, workload_digest, configuration_digest, unit, coefficients (keyed by those dimensions plus unit conversion), conversion_revision, receipts, observed_at}`, `conversion_digest=sha256(JCS(M7 without signature))` (Scenario 71).

**Signed M-records.** Every capacity input except M6 is a signed record `{value,n,units,estimator,configuration_digest,exposure,window,missingness,observed_at}` with an owner: M1 Sol, `baseline_items_per_h` with `status ∈ {provisional, measured}`; M2 Astra, execution tails; M3 Opus, per-role cost bounds and the pinned `u_r=0.70` (unmeasured); M4 Luna, `lambda_j` (arrivals per exposure hour), `service_demand(j,r)` (resource-seconds per arrival, failures and retries included), `transitions_per_item` (from journals) and measured resource capacity; M5 Sol, `providers[p]`; M6 reducer, the ledger below authenticated by its signed replay closure; M7 Opus, the conversion above. Units must be compatible; a missing, unsigned or incompatible input resolves to UNKNOWN, which forbids the dependent scale claim (§9) (Scenario 44).

**Obligations as a ledger.** M6 is `{provider, account_id, unit, as_of, usage_receipts, outstanding_by_role, recovery_reserve, R_p, unknown_terms, conversion_digest, provenance}` with `R_p = Σ known remaining_cost_bound(subject,role,p) + h_p`, exact over known estimates, receipts deduplicated; UNKNOWN terms (an unknown h_p included) are excluded and reported as `unknown_terms {count, roles}`, marking R_p PARTIAL_ESTIMATE, never a proven consumption lower bound; `recovery_reserve = h_p = max(previous_h_p, 2 × new_subject_cost_bound_p)` (`provisional`); a larger admission raises h_p for future accounting, never revising an earlier grant. Deterministic roles cost zero provider units; reconciled usage is deducted once; obligations shrink only through reconciled consumption or release after confirmed worker stop (§2; Scenario 58).

**Admission.** The configured initial capacity is `executors=5 (provisional)`; actual admissions require owner-authorized eligible subjects and §3 seat feasibility in both budget modes. On mlv-app runners reproducing `prompt_too_long` refusals, check provider context limits before dispatch; reshape oversized inputs while other work proceeds. Initial cost-bound calibration has TTL `30 min (clock_domain=real, provisional)`; expiry sets status UNCALIBRATED. In `throttled` mode the planned new-inference dispatch rate is multiplied by `max(0.25, min(1, budget_p / max(R_p,1)))` for compatible fresh units, by 1 when evidence is UNKNOWN or STALE; review obligations are scheduled ahead of new implementation (Scenarios 41, 45, 59).

**Latch episodes, outbox, parking, clearing and rotation.** A latch is an authenticated provider refusal or failed authenticated probe for p, never a budget shortfall. `refs/oracle/global/latch/<p>` is a mutable CAS pointer (§2) to the current immutable episode-state object `refs/oracle/global/latch-episode/<digest>` = `{latch_id, generation, predecessor_digest, state: OPEN|CLEARED|ROTATED, opened_receipt, cleared_receipt, success_count, outbox_seq}`, `latch_id = sha256(JCS([p, account_epoch, first_failed_receipt]))`. An episode opens only when p has no OPEN episode; a repeated refusal reuses it. The opening transaction CASes the latch pointer and `refs/oracle/global/outbox-head` `{seq}`→`{seq+1}`, creates the immutable `refs/oracle/global/outbox/<seq>` = `{seq, kind, p, observed_at, latch_id?}` and commits LATCH_OPEN effects and cursors together; replay cannot create another. **Relay.** The sole authorized mailbox writer, `oracle-outbox-relay.py` under an append-helper witness identity (never the reducer), runs on every sidecar `--ensure` tick and floor wake (§1) under `Global\ConjugalOracleRelay-<§7 identity hash>` (a loser exits 0, writing nothing). Stage `<kind> <p> <observed_at> [outbox:<seq> latch:<latch_id>]` once per seq by private-index CAS on non-checked-out `refs/oracle/mailbox`, seeded from master. Retry from that ref, never HEAD; eight losses under §1 backoff yield RELAY_CONTENDED. The same writer lands entries into master's `coordination/comms/opus.md` through authorized normal-index integration under a reducer-issued whole-checkout path allocation for reserved subject `relay-land`; staged peer dirt or divergent targets defer. Merge against fresh master plus archives, preserving unrelated content and permanent markers. Existing staged markers prevent restaging. CAS `outbox-relayed` only after verifying delivery in master; restart repairs cursor lag. Relay failure preserves the outbox and never blocks certified delivery; clearing and rotation never cancel pending delivery. Only operations needing inference from p park, each affected subject getting one WAIT-ACCOUNT record `{p, latch_id, resume_on: LATCH_CLEARED|ROTATION_COMPLETE}` with its semantic timers suspended (§3). **Clearing** binds the current generation: two consecutive successful authenticated inference probes on the unchanged account fingerprint, at least `120 s (clock_domain=real)` apart with no intervening refusal (a refusal resets `success_count`), publish a CLEARED successor, LATCH_CLEARED, an informational outbox entry (kind LATCH_CLEARED, never ROTATE_REQUEST) and the resume obligations in one transaction; a clear citing a stale generation is inert; account_epoch is unchanged. `ROTATION_COMPLETE` binds latch_id, a changed account fingerprint and a passing authenticated inference probe on that account, publishes a ROTATED successor and increments `account_epoch[p]`. Either resumption requeues every parked obligation once (§3) without duplicate claims; a completion naming another latch_id is RECORDED_NO_EFFECT. A refusal after authenticated recovery has a new first failed receipt, hence a fresh episode, generation and outbox entry (Scenarios 23, 30, 72).

## 6. Policy and migration

**Trust anchor.** Genesis is a state commit naming the owner root key, every lane, reducer, witness, custody-principal and emergency public key, `lane_family`, the canonicalization identifier, the qualified checker digests, the corpus digest and the auth-tool digest. `genesis_sha=sha256(genesis content)` is pinned by an owner-verified installation outside repository-controlled policy at `~/.claude/oracle/anchor.sha`, owned by a distinct owner SID with protected non-inherited ACLs (`icacls`, runners read-only) and parent directories protected against deletion, replacement and reparse substitution; reducer, launcher and every checker verify owner, effective ACL, file identity and the anchored genesis/policy-chain digest at start (refusing on mismatch) and at every amendment (holding the validated file open without write/delete sharing through publication, rejecting the amendment atomically on mismatch), evidence retained for replay; pre-policy trust is exactly this set. The initial policy requires the root signature plus one keyholder from each family. Checker qualification (QUALIFY) binds executable, source, dependency, corpus and result digests, requires an independent cross-family review envelope and passes every adversarial vector of the signed corpus (`40 fixtures, 10 adversarial, provisional`); enrolling an attestation helper (§4) is a QUALIFY also binding its custody principal's public key, ACL attestation and family. REVOKE of a key or checker requires matching envelopes (target key, scope, evidence digest) from one currently eligible non-target keyholder per family under the prior policy; a family emergency key (§0), enrolled at genesis or by amendment, substitutes for its own family's unavailable signer for REVOKE only. A single authenticated COMPROMISE_REPORT freezes the affected authority through a recorded challenge pending that quorum but cannot revoke, appoint or authorize delivery. REVOKE is receipt-sequenced: authority created at or after its receipt is invalid, pending adoptions citing it are held until re-attested by a still-qualified pair, and historical replay retains its original closure. Amendment requires two matching POLICY new_sha envelopes, one eligible keyholder per family under the prior policy, within `30 min (clock_domain=oracle)`; select the earliest first receipt among fully matched unexpired proposals, digest as tie-break; expired/unselected proposals are recorded; apply at the next batch boundary and increment policy_epoch (Scenario 38).

Every amendment includes an explicit in-flight migration map: retain the subject's old pinned policy through completion, or cancel/supersede with fresh verdict_ver, assignments, reservations and verification under the new policy; missing entries for open subjects reject the amendment; old votes and idempotency keys are never relabeled; old and new policy, signatures, receipt times and migration disposition are pinned (Scenario 56).

## 7. Signing, custody and reducer identity

Use Ed25519 over canonical JSON envelopes; no shared symmetric secret. Private keys reside under `~/.claude/oracle/keys/<actor>.ed25519`; public keys and rotation history under `coordination/oracle/keys/`; `key_id=sha256(pub)[:16]`; signer must equal actor. Where families share runner SIDs, signing requires family-isolated custody denying other-family key reads and signing requests; otherwise cross-family signing is unavailable, never inferred from distinct keys. Reducer, optional sol-adopt and each custody principal (§4) have separate identities; a principal's key file, scheduled-task configuration and binary carry ACLs excluding every lane runner; sidecars retain their lane actor; append helpers use genesis-enrolled witness actors with protected code/keys excluding their lane runners, deriving signed `timing` from local clocks, never caller timestamps (Scenarios 19, 65).

An unsigned pending row has no authority; its signature must arrive within `60 s (clock_domain=oracle)` of receipt. Rotate keys after `25 d (clock_domain=real)` with an old-key-signed new-key entry; hard-block new signing after `30 d (clock_domain=real)`; where a bench profile forbids lanes writing outside the repository, the owner rotates, requested by one KEY_ROTATE_REQUEST outbox entry (§5, `p`=key_id) when rotation falls due, and subjects needing a hard-blocked key record WAIT-CUSTODY; old-key new receipts have grace `24 h (clock_domain=oracle)`. Reducer mutex identity is the file identity of the absolute, handle-resolved `git rev-parse --git-common-dir`: `CreateFileW(FILE_FLAG_BACKUP_SEMANTICS)` and FILE_ID_INFO; `Global\ConjugalOracle-` plus hash of VolumeSerial and FileId128; fallback resolves the handle path through VOLUME_NAME_GUID, NFC and casefold. The security claim covers individual faulty signers and cooperative runners under mutation admission, which with lanes sharing one `.git` under one OS principal (measured on Conjugal) is cooperative wrapper admission, not an OS boundary, tolerating one independently faulty signing lane where distinct-seat checks require another identity; excluded are common checker bugs, shared administrator compromise and wrapper bypass (Scenarios 53, 65).

## 8. Clocks, stubs and fault injection

Every duration in prose, policy, fixture and metric has `clock_domain=real` or `clock_domain=oracle`; table cells declare it; a duration-valued variable inherits its defining domain; arithmetic never mixes domains without an explicit mapping; rates use real calendar time; deadlines carry domain and persisted origin. The clock/schema lint rejects missing domains, ambiguous literals and inconsistent expressions (Scenarios 36, 43, 67).

```
oracle_now = oracle_t0 + (real_now - real_t0) * SCALE + OFFSET
```

Production fixes SCALE=1/OFFSET=0. Test overrides require ORACLE_TEST_MODE=1; persist real_t0 (`clock_domain=real`) and oracle_t0 and OFFSET (`clock_domain=oracle`), all in seconds.

**Comparability.** The reducer issues, under its verified lock (§7), immutable `oracle_mapping = {boot_id, map_seq, qpc_origin, qpc_frequency, oracle_origin, SCALE, OFFSET, uncertainty_s (clock_domain=real), prev_digest}` objects at `refs/oracle/global/oracle_mapping/<digest>` (§2); every helper `timing` and persisted deadline names its mapping digest. Two timestamps are comparable iff they name the same mapping, or the reducer has published an immutable BRIDGE `{old_digest, new_digest, calibration_evidence, bound_s (clock_domain=real), signature}` between their mappings, calibration_evidence being retained QPC anchors and append-helper-signed `timing` receipts spanning both mappings, never wall-clock subtraction; missing bounds yield BRIDGE_UNAVAILABLE. A comparable timestamp is the closed interval `[t − u, t + u]`, u the summed uncertainty. **Test isolation.** Every ref, journal, key and runtime path resolves through one `oracle_ref(path)` function. Under ORACLE_TEST_MODE=1 it maps refs to `refs/oracle-test/<run_id>/…`, journals and state to `coordination/oracle/tests/runtime/<run_id>/`, and keys to a per-run test key directory whose key_ids are never in production genesis; any production `refs/oracle/*` target or key_id exits 2 with zero writes; unset, it refuses every `refs/oracle-test/*` target and test key. SUBSTRATE rows run in per-row clones; the namespace is deleted after receipts are archived. Helper scheduled tasks (§4) under test carry the injective name `(repository_id, run_id, fixture_instance, role, request_id, attempt)`, a bench profile requiring a fixed project prefix prepending it to that complete tuple, run_id persisted before registration and reused on recovery; cleanup addresses exact registered identities, never prefixes. Each fixture declares clock_driver=wall or virtual; SCALE=60 is permitted only for STUB with injected virtual clocks for both domains and no external floor dependency; SUBSTRATE, MIXED, RUNTIME fixtures and any floor-wake check (Scenarios 5, 52) use SCALE=1 and wall clocks. The harness rejects an unclassified row or invalid scale/driver combination.

Stubs emit real signed envelopes through git/filesystem/reducer with provider_calls=0; latency comes from a pinned fixture distribution and declared virtual-clock advances. MIXED(n) means exactly n real provider calls, n≥2, the ledger equal to declared calls including retries; RUNTIME calls are measured per level (§11).

Fault controls under `coordination/oracle/tests/runtime/faults/`: `probe-fail`, `reducer-drain-stop`, `latency-ms` (`clock_domain=real`), `notify-drop`, `ref-lock-hold` (`clock_domain=real`, seconds), torn-frame offsets and injected checker outputs (Scenarios 0, 27).

## 9. Throughput plan and G-MEASURE

**Delivery baseline.** An item is one subject first receiving an authorized ADOPTED record for its exact candidate, counted once; REJECTED, READY, WAIT-ACCOUNT (parked exposure), failed and superseded work have separate counters. `metrics/items.jsonl`, bounded, listed in `.gitignore` and reconstructible from retained authoritative receipts, records all transitions plus a per-subject waterfall: admission queue, execution by role, floor/dispatch delay, verification/adoption queues and retries. Baseline uses matched work complexity, acceptance criteria, provider configuration and calendar exposure of `336 h (clock_domain=real)` (Scenario 63-0), parked exposure included; `baseline_items_per_h` (b, M1) is `provisional` until measured; `b=first_adoptions/elapsed_calendar_hours`.

**Order of work.** First, when measured reducer saturation binds, the §1 pipelining lever, qualified or left disabled by Scenario 68 alone. Next, reducer-owned immediate helper/adopter dispatch (§1, §4), measured through matched five-executor adoption waterfalls: unchanged READY→ADOPTED delay with the floor sweep disabled, a matched-rate `CI95.upper ≤ 1`, growing downstream queues or any safety regression falsifies its benefit. Then, after helper custody portability (Scenario 69) and downstream capacity pass, ramp executors 5→9→15 through G-MEASURE: ideal `2×/3.6×/6×`, targets `2×/3×/5×` (`target_multiple` m); no sharding precedes a separate closure/replay proof.

**Resource gate and provider forecast.** For every resource r (implementation, each V seat, each checker, adopter, reducer, provider concurrency, shared-checkout mutation) the scale claim requires `sum_j(lambda_j × service_demand(j,r)) ≤ u_r × available_capacity(r)`, with `available_capacity(r)=3600 × concurrent_slots_r` resource-seconds/hour over matched workload classes j, every term a §5 M-record, all `clock_domain=real`; for r=reducer this is exactly `D_N ≤ 0.70·μ` with stable queues (D_N from §1, μ the production depth's prediction); blocked path time counts as service demand. For each provider p report `F_p = target_rate × horizon_p × mean_total_units_per_delivered_item_p`, where `target_rate = target_multiple × baseline_items_per_h` and `horizon_p` is the length in `h (clock_domain=real)` of the provider's allowance interval ending at `reset_at` (UNKNOWN when null), the mean including all allocations, failures, rejections, retries and parked work in the window, in the §5 unit; compare F_p with W_p when known, else UNKNOWN; zero delivered items leaves F_p UNKNOWN (§5).

**2a gate.** The first three real end-to-end items at each level pass independent replay; then at least 20 additional adopted items at that level within a forecast `5 h (clock_domain=real)` allowance; insufficient completions record a failed forecast at expiry, retaining extension exposure separately while collection continues. Zero safety failures, reconciled obligations and complete waterfalls are required before the soak.

**2b gate.** At each executor level with target m ∈ {2, 3, 5}, planned observation is `T_m = max(48, 100 / (m × b)) h (clock_domain=real)`; observe two consecutive non-overlapping windows each at least `T_m/2` (never below `24 h (clock_domain=real)`), totaling at least 100 adopted matched items; provisional or zero b plans at the `48 h (clock_domain=real)` floor and yields absolute rates only. When T_m exceeds `72 h (clock_domain=real)` the longer window is declared before starting and extended when observed yield is below plan; at cumulative `2T_m` the reducer closes the attempt as INSUFFICIENT, retaining exposure, continuing safe production and scheduling an owned follow-up measurement. At window start the reducer publishes the immutable window definition `refs/oracle/global/measure/<level>-<window_id>` (§2) = `{start_receipt_seq, planned_end (clock_domain=real), configuration_digest, boot_id, mapping_digest}`; progress lives separately in the mutable CAS ref `refs/oracle/global/measure-checkpoint/<level>-<window_id>` = `{last_receipt_seq, boot_id}`, published through the reducer every `10 min (clock_domain=real, provisional)`; items, queue depths and exposure derive from receipts and `refs/oracle/adopted/*` between the boundaries; a reboot resumes the window, downtime counted as exposure. A configuration change invalidates qualification without deleting exposure. Per window require nonpositive end-minus-start queue depth for verification and adoption, no positive fitted queue-depth slope and unchanged acceptance; saturation experiments use owner-authorized eligible backlog only; absent backlog records INSUFFICIENT and dispatches no experimental work.

**2c gate.** Analyze within a forecast `2 h (clock_domain=real)` allowance after 2b and G-MEASURE. The result is one signed record `measured_multiple = {level, baseline_M1, configuration_digest, exposure_h, window_receipts, actual_rate, ratio, CI95:[lower,upper], method, S_receipt, 20_receipt, 50_receipt, 68_receipt, status}` using a predeclared stratified bootstrap; session-correlated benches resample independent project/session clusters, preserving order and reporting cluster counts. A claimed target requires matched windows, valid S/20/50/68 safety and capacity receipts, the resource gate, and `CI95.lower ≥ target`; failed claims remain reported. Nine executors require a qualified five-executor 2× result plus measured reviewer capacity; fifteen require 3× at nine.

**Measurement qualification.** The §5 M-records M1–M5 and M7 additionally carry `{method, confidence_interval, source_cmd, receipts, model, effort, policy_sha, workload_digest}`; M6, an exact ledger, carries `provenance` only and no confidence interval. Configuration tuple changes invalidate forecasts immediately; the default maximum age is `7 d (clock_domain=real)`, unmeasured, unless §5 states a consumer-specific TTL.

A qualified p99 requires a predeclared distribution-free order-statistic bound with at least 95% coverage, sufficient independent samples and a recorded precision assessment, otherwise H stays at its §2 default; cost bounds likewise require a documented conservative method (Scenarios 44, 62).

## 13. Residuals

1. **Required semantic-family absence.** A provider latch parks that family's new inference (§5) until the episode clears or the owner rotates the account; the bound is `min(time-to-clear, time-to-rotation)`, the latter unguaranteed.
2. **Empirical calibration and capacity.** All provisional parameters, forecasts, capacity and custody portability require measurement.
3. **Unavailable execution authority.** Failed Job Object termination, inaccessible runners/keys, a missing family revocation key or unbridgeable clock mappings leave a durable blocked subject or blocked revocation; losing every enrolled helper of either family (both, under §0's four-helper configuration) prevents every new SEAL fleet-wide until still-qualified custody recovers or a §6 QUALIFY enrolls a replacement; a scheduled floor that never fires leaves supervision, relay and dispatch unbounded with zero leased executors.
4. **Common failure domains.** Shared-host compromise, storage durability violations and correlated defects across implementations remain outside the single-fault assurance (§7). Receipt growth performance and hostile shared-SID signing isolation require qualification; denied landing authority leaves mailbox delivery unbounded.
