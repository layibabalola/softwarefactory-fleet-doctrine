# Profile: creative-writing - Fiction, scripts, long-form creative text

**Profile of** `specs/fleet-factory-kernel.md` r1. **Profile revision:** r1. **Status:** `DRAFT - NO BENCH`. **Benches:** none.
A profile defines what acceptance means in its domain. It never weakens a kernel clause (kernel §5). File evidence against it as `P:creative-writing <field>` lines in `adjudications/factory-kernel/<project>.md`.

| Field | Rule |
|---|---|
| Subject identity (K3) | document content digest, plus the digest of the outline or series bible it was written against |
| Artifact store | git or a document store with version history |
| Determinism class | judgment: no automated pass/fail |
| Acceptance evidence (K5) | a rubric panel (continuity, motivation, voice, tone, fit to the brief) scoring the exact draft with quotes, plus the owner's or editor's acceptance for anything published |
| Independent key (K6) | an editor or reader other than the author; a model panel counts only when it is cross-family and bound to the rubric (R3, R9), and it is never the sole key for publication |
| Resource terminals (K5) | none beyond quota; running out of panel quota is a terminal, not an approval |
| Delivery target (K7) | the published or submitted manuscript version |
| Human gates (K2) | publication, voice and brand decisions, anything under the author's name |
| Budgets | panel calls per draft; owner reading time |
| Stress on the kernel | the design-loop protocol applies directly: its lint becomes continuity, motivation and tone, and its proof becomes a read-through (`specs/design-loop-protocol.md` §2) |
