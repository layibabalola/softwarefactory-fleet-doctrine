# Profile: code - Software source code (desktop, web, services, tooling)

**Profile of** `specs/fleet-factory-kernel.md` r4. **Profile revision:** r4. **Status:** `BENCHED`. **Benches:** cloudvore, conjugal, salesforce-tools, adversarialllm, agent-bridge, adobe-ingester, airmypc (build lane), mlv-app (source and tooling).
A profile defines what acceptance means in its domain. It never weakens a kernel clause (kernel §5). File evidence against it as `P:code <field>` lines in `adjudications/factory-kernel/<project>.md`.

| Field | Rule |
|---|---|
| Subject identity (K3) | git tree OID of the candidate commit as it will be delivered, after any merge with the delivery target; a key on a different tree does not transfer. Generated binaries are identified by the build receipt's output digests; for code/design-review subjects, components are the subject blob OID, bench HEAD OID and rubric digest, in that order, combined by K3 |
| Artifact store | git (shared checkout or worktrees); build outputs are not the subject |
| Determinism class | deterministic by default; flaky suites are declared per test, never silently retried |
| Acceptance evidence (K5) | the project's pinned acceptance checks for the declared artifact kind run at the exact commit and declared environment, including interpreter and TEMP/TMP where applicable (for example N identical green runs), executed or authenticated; replay agreement alone is not acceptance (Approach A Round F1, cluster C3). Bind durable acceptance receipts by content digest; log offsets are locators only. Documentation, doctrine and code/design-review subjects declare the rubric and required roles before work; acceptance requires their completion receipts and an independent acceptance decision bound to the exact subject |
| Independent key (K6) | a verifier from another model family (R3), a CI runner the producer does not control, or an attended human verifier other than the producer named by the register |
| Resource terminals (K5) | suite timeout, thermal admission, runner capacity, independent key unavailable: typed terminals, no partial green; parked work names its resume condition and the actor who can satisfy it. Owner-only resume conditions are sent through the register's escalation channel when the park is recorded; work not requiring the unavailable resource continues |
| Delivery target (K7) | integration branch via the project's landing path; for feasibility subjects, the owner decision record; review branches push (R7) |
| Human gates (K2) | releases, security-sensitive paths, frozen bytes, and anything the project's register lists; the register is reachable from every session checkout, classifies fleet-tool writes including permitted locations, names an owner-facing escalation channel, and takes precedence over bus prompts' procedural defaults |
| Budgets | wall time per suite, provider calls per subject; review rounds also report dispositions completed and subject changes, including zero; zero changes alone does not determine health |
| Claims (K3) | leases name the subject, owner, expiry and owned processes, identifying the live holder rather than a short-lived lease-writing helper. A mutable checkout another project executes from is itself a claimed subject; same-host cleanup reads the lease before acting and never kills by command-line pattern alone |
| Dispatch preflight (K9, K10) | the spending tool runs the project's resume gate before dispatch and retains its result, the inventory snapshot and digest, and account-parity evidence. Inventory verification uses the launcher path dispatch uses; resume failures identify each losable item and its writer; failed or stale checkpoints name their last passing time and resume condition; launcher diagnostics are retained, and a CLI invocation failure is not evidence that a model is absent |
| Stress on the kernel | shared-checkout index races, worktree-scoped locks, and plumbing commits onto a checked-out branch (all three measured in Round F1); cross-project execution of a mutable tool checkout and pattern-based process kills on a shared host (airmypc, 2026-09-14) |
