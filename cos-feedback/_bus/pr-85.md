## Blockers

- **Ruleset path: deletion-before-first-run fails open.** `docs/review-key-publication.md` Rule 2 (and Amendment 4/5 + the dry-run checklist) claim a pub deleted before any verifier run fails closed via `issue_comment.deleted`. On the **App path** that works: the deleted-payload run posts a new App check carrying the `deleted` log. On the **ruleset path**, the same section says an `issue_comment` run cannot update the gate and must `POST .../actions/runs/<id>/rerun` the required workflow's latest `pull_request` / `pull_request_target` / `merge_group` run — and the check-to-workflow mapping accepts only those events (not `issue_comment`) for mark read-back. A re-run does not carry the `issue_comment.deleted` payload, and the deleted comment is gone from the comments API, so a pub that never entered the mark can be deleted with no durable `deleted` record → fail-open. Personal `layibabalola/*` repos are App-only, but org consumers (e.g. `SuperDimensionalSpaceFortress/MLV-App`) may choose the ruleset path.
  - **Unblock (pick one):** (a) let the `issue_comment.deleted` run of the verifier write a mark-bearing check and expand mark-union mapping to accept `issue_comment` (and `workflow_run`) runs of the pinned workflow for **mark read-back only** (protection still only from required-workflow events); or (b) persist deleted pub ids to a durable PR-scoped store the re-run reads; or (c) carve the pre-first-run deletion guarantee as **App-path only** in the spec, Amendment 5, threat model, and dry-run checklist, and require the App for any consumer that needs that property.
