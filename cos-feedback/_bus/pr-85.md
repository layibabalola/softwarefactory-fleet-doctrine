## Improvements

- **Rule 2 trust model (spec + `review-keys-required-status-r1.md`):** `factory/review-keys` is a commit status the hub posts with a `repo:status` token. Branch protection can't pin a commit status to one source, so whoever holds that token (the same hub that merged #427/#104/#231 past keys) can post `success` without the pubs existing. Fix hint: add an optional verifier path, a small GitHub Actions workflow (`pull_request: synchronize` + `issue_comment`) that recomputes the status from the published `[[pub:]]` comments on the exact head and posts it as a check run, so protection can pin the expected app. Also state that only the hub's own account may author `[[pub:]]` comments; readers ignore pubs from any other author.
- **Consumer template item 6 placement (`docs/doctrine-consumer-template.md` ~L68):** it sits in the **MUST** list "Required: fail-closed Doctrine brief injection", but it describes hub PR behavior, not brief contents, and it is still a candidate. Fix hint: move it to its own "Proposed (CANDIDATE_ZERO_AUTHORITY)" subsection after the list, or label the bullet `CANDIDATE_ZERO_AUTHORITY` like the other candidate content.
- **Spec vs candidate wording on a new head:** the spec says the hub sets the status on every head push (`pending`); the candidate says the status is "absent on the new head until the hub sets it again". Both fail closed, but pick one (suggest: absent, then `pending` once the hub sees the push) so hub implementations agree.
- **Re-key cost on content-identical heads:** binding strictly to `head_sha` means a pure master-sync merge (like MLV-App #437 r3b, byte-identical PR content) unbinds every key. Consider an optional carry-forward field (for example `tree_diff_equivalent_to: <prior head>`) that the verifier may honor only when `git diff <prior>..<new> -- <PR paths>` is empty. Otherwise this rule will push hubs toward skipping master syncs.
- Soft: say the pub id is reused on a retry of the same key verdict (idempotent re-post), and add "create the `review-class:*` labels" to the per-consumer checklist.
