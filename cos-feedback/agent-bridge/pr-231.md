# agent-bridge PR #231 — OUTBOX-CARDS-1N r5+r6: R15 safe-outcome narrowing, FX8e roots never raise

Later push to tip `91241d4` (6 commits, +3847/−44, 16 files). Class C. Covers r5 (`c7aec4c`, not separately published) and r6 (`91241d4`). Delta since the last CoS read (`a8d29b6`): +149/−35, 2 files (`test_doctrine_outbox.py` +145/−32, `tools/doctrine_outbox.py` +4/−3).

**Why r5/r6 exist:** r4's Windows CI went red on `R15[bus_unc]`: with `--bus` spelled as UNC, git refused to open the bus, the drain stopped before ever launching the validator and printed an empty report, and R15's `assert calls` failed. That is a fail-closed outcome, not a safety hole.

**r5/r6 delta:**
- FT4/FT6 `assert_safe_drain_outcome`: R15 now accepts exactly two outcomes. (A) validator launched, every launch's node outside the bus clone and cwd by file identity, `CARD_INVALID` exit 1, nothing published. (B) no launch, accepted ONLY for the four alias root spellings (`bus_*`, `cwd_*`) and only with exit **2 exactly** (r6 tightened from "non-zero"), no publication, no marker, bare master unchanged, plus a `UserWarning` carrying the exit code and first stderr line. The seven PATH spellings must still take (A).
- `drain_bus_arg` now returns captured stderr so failures show exit, stdout report and stderr.
- R18: forces `bus_fetch` to raise `GitError` for `bus_ext`/`bus_unc` and proves R15 takes (B) with the warning (kills M33 publish-before-stop, M34 exit-0-no-launch); warnings recorded via `catch_warnings` so an R15 failure is reported as itself.
- R19: forces `same_file_as_a_root` to False and proves the FX6 string check alone still refuses a plainly spelled bus/cwd node (kills M27s), with a no-roots control.
- FX8e (product code): the roots computation in `find_node` (`node_excluded_roots`, `os.getcwd`) now catches `Exception`, not just `(OSError, ValueError)`, returning None (COULD-NOT-CHECK). Test cells for RuntimeError from either.
