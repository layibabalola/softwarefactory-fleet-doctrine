## Improvements
- Soft (new): `except Exception` in `find_node` makes any programming error (TypeError, AttributeError) in the scan look like "no usable node" and turn every card COULD-NOT-CHECK with no hint why. Fail-closed is right, but consider logging the swallowed exception type at debug level, or narrowing to `(OSError, ValueError, RuntimeError)` plus a test, so a regression is visible instead of silent.
- Soft (new): `same_file_as_a_root` calls `samefile` against every root at every ancestor. If an exclude root (for example a private temp dir) is gone or unreadable when `find_node` runs, every candidate fails the identity check and the drain is COULD-NOT-CHECK. That is fail-closed, but a pin asserting the exclude roots exist at each `find_node` call site (or a distinct detail string for "excluded root unreadable") would make that failure mode diagnosable.
- Soft (new): FX8a rejects forward-slash Windows entries (`C:/nodejs`). Fine fail-closed, but worth one README clause so an operator with such a PATH knows why node is "absent".
- Superseded: the earlier `path_is_within` string-prefix invariant note is now mostly moot, since file identity is the authority and the string check is secondary. R17 sibling-prefix test covers the main risk.
- Optional (carried): in `drain`, the COULD-NOT-CHECK rebuild path (`attempt -= 1; continue` inside `try`/`finally`) would benefit from a one-line comment that `blocked` is sticky across attempts.
- Optional (carried): `make_validator_bus` omits `specs/<dir>/` entries from the private roster; pin or vendor-README note at re-vendor time.
