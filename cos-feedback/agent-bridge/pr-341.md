### Bounded regular-file read

https://github.com/layibabalola/agent-bridge/blob/9fe4c31a969632bc0886898893aab5a78713a9cb/core/storage.py#L727-L751
https://github.com/layibabalola/agent-bridge/blob/9fe4c31a969632bc0886898893aab5a78713a9cb/core/storage.py#L682-L714

The installer always supplies the fixed positive cap 65536. The helper opens once, fstats that same handle before reading, and returns at most the cap; a cap+1 read detects oversized input without loading the entire file. Checking descriptor type avoids a separate-stat type check being invalidated by a later pathname replacement. On POSIX, O_NONBLOCK prevents a FIFO open waiting for a writer, then S_ISREG rejects it without attempting a data read. Directory/device/socket cases either fail opening/wrapping or fail the descriptor check. On Windows the existing shared-read adapter retains READ/WRITE/DELETE sharing, binary mode and ownership cleanup. Existing storage functions are unchanged. Both normal and exceptional read/check paths close the handle; fdopen failure closes the raw POSIX descriptor.

The cap bounds requested returned data and memory order, not strict physical I/O: BufferedReader can prefetch a bounded buffer. It also is not a wall-clock timeout for regular-file I/O. Network filesystems are already unsupported by storage's stated model. O_NONBLOCK is not a universal deadline mechanism, nor protection against every exotic filesystem/device open. Those are platform/threat-model limitations, not evidence the local regular-file/FIFO fix is ineffective.
