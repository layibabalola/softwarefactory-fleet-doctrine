## Improvements
- Silent fail-open when the interpreter is missing (new, worth fixing in this PR): the Test-Path guard checks only the script. On any host or seat where `$env:USERPROFILE\AppData\Local\Python\bin\python.exe` does not exist, `& "<missing>.exe"` raises CommandNotFound, `$LASTEXITCODE` stays null, and `exit $LASTEXITCODE` exits 0, so the tripwire is inert with no signal. Guard the interpreter too and exit 1 with a stderr line (non-blocking but visible), and add a test cell with a non-existent interpreter that asserts a non-zero, non-2 exit plus the message.
- Bare-push gap (new, soft): T5 needs master spelled in the command, so `git push`, `git push github` or `git push github HEAD` from a checkout on master with upstream github/master is not caught. That is the most likely careless-session form. Either add a DECLARED OUT row saying so, or deny a push with no explicit refspec (the hook cannot know the current branch, so this would be text-only and conservative).
- T4 and T2 also deny reads (new, soft): `gh api repos/o/r/git/refs/heads/master --jq .object.sha` and `gh api repos/o/r/pulls/5/merge` (GET, merged check) are read-only but match. - T1 is order-free across the whole command (declared), so compound commands like `gh pr checkout 5 && git merge master` in a lane worktree will deny. Accepted for a tripwire; the deny message's "split the command" advice covers it. One DECLARED row pinning that as an expected false positive would stop a later "fix" from silently narrowing T1.
