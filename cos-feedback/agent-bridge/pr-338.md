Previously, a caller passing pid=None and the matching generation satisfied ownership when that helper also returned None. Heartbeat then rewrote the malformed lease, and release unlinked it.

Both changed functions now bind owner_pid once and reject owner_pid is None before testing caller equality or generation. Refusal occurs before heartbeat mutation/write and before unlink. Existing acquisition-sidecar locking, OSError handling, generation checks, parser conversion, lease_status and acquisition logic are untouched. For an integer parsed owner, the new first term is false and the previous ownership expression remains, preserving the stated integer-owner behavior. Missing/null values still become zero rather than None. This is static source reasoning; no code was executed to establish it.
