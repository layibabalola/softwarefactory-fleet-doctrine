PowerShell reads a line that starts with a quoted string as an expression, so pasting it gives a `ParserError` ("Unexpected token" / "You must provide a value expression following the '/' operator"). (3) A `$` inside a quoted path with a space is expanded by PowerShell and POSIX shells, so the line names a different interpreter. Harm: a high-severity remedy that claims to be runnable either fails to parse or runs a shell-split fragment, in the exact case where the operator is relying on it to restart a stale watcher. Tests (`test_health_remedy_runnable.py:180`, `:361`) run `shlex.split(posix=False)` and call `main()`, so they never go through a shell. **Unblock:** check the interpreter and script tokens with `_safe_double_quoted_arg`, always double-quote them, and put PowerShell's call operator in front (`& "<python>" "<script>" ...`; or emit a cmd/pwsh-neutral form), otherwise make the remedy manual.
