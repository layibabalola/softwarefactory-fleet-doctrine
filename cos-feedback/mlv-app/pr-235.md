## Blockers

- **Locked worktrees are mutated before the remove is refused (carried unchanged from #234; confirmed in code).** `Invoke-SweepMergedLaneWorktrees` builds candidates from `git worktree list --porcelain` (`tools/coordination/Retire-LaneWorktree.ps1:163-172`) and reads only the `worktree ` lines, so `locked` / `prunable` entries are never filtered. The unchanged gate then moves ignored non-debris files into quarantine (`:121`) and runs `git clean -fdX` (`:124`) **before** `git worktree remove` (`:125`, no `--force`) refuses the lock. Result: a merged, clean, idle worktree that someone explicitly `git worktree lock`ed has its build/cache dirs deleted and its ignored evidence relocated, then is reported `kept: remove-failed`. A lock is git's one explicit "don't touch" signal, and the sweep is on by default at every lane exit against all of `C:\mlvtmp`. **Fix:** in the porcelain loop, track the current entry's `locked` (and `prunable`) lines and skip that worktree before the gate (count it as `kept{locked}`); add a test that a locked merged candidate is neither quarantined nor cleaned.
- **No mutual exclusion around a default-on destructive sweep (carried unchanged from #234; confirmed in code).** Nothing in the sweep or in `Invoke-Lane.ps1:1570-1582` takes a lock. Lanes exit concurrently (parallel tracks / swarm lanes), so two sweeps gate the same candidate list at once and race the quarantine `Move-Item` / `clean -fdX` / `worktree remove`. The gate's live-process probe (`:88`) is a point-in-time command-line snapshot, so a lane that starts in, or a dispatcher that reuses, an older clean merged worktree after that probe can have it cleaned and removed underneath it (the 6 h young guard does not cover reuse of an older tree). **Fix (minimum):** take a host-wide named mutex or lock file for the whole sweep and skip the sweep (record `skipped: sweep-locked`) when it can't be acquired. Ideally lane startup/reuse respects the same lock. Acceptable alternative: ship the sweep default-off or `-WhatIf`-only until both Blockers are closed.
