- Soft (reviewers should confirm): the aggregator uses `if: ${{ always() && !cancelled() }}` (`.github/workflows/tests.yml`, job `repo-hygiene-python-windows`). A shard that fails, times out or is cancelled makes the aggregator fail, as the comment says. But if the whole run is cancelled (for example a concurrency cancel or a manual cancel), the aggregator is **skipped**, and branch protection treats a skipped required check as passing. Other required jobs would normally be cancelled too, so this is soft. Prefer `if: always()` so a cancelled run reports the pinned check as failed, or state why skipped is acceptable here.
- Soft: `tools/repo_hygiene/ci_unittest_shard.py` weights modules with a hard-coded `MEASURED_SECONDS` table from one run (PR #225, run 36992317962). Coverage is safe: `--verify-partition` fails if the shards are not disjoint, miss a module, or do not hold exactly the test count that `unittest discover` collects, so a test inside a subpackage that `glob` would miss is caught by the count check. Balance will drift as modules grow, though. Consider a hygiene pin or a note naming who refreshes the table.
