## Improvements
- **The refutation is weaker than the commit message says.** `processHeapsValid()` (`test_paused_render_recon_overlap.cpp:107-118`) only checks heap metadata via `HeapValidate`. Without page heap or ASan, an overrun into a neighbouring live block, or a write into freed-then-reused memory, passes it. And on non-Windows CI it returns true unconditionally. Run the stress mode (`MLVAPP_PAUSED_RECON_OVERLAP_ITERATIONS`) once under full page heap (`gflags /p /enable pipeline_tests.exe /full`) or an ASan build before calling the candidate refuted, and record the result in the PR body. Until then, call it "not reproduced at the library level".
- **The harness may not match the stop-time overlap.** The recon worker runs frames 0-2, the paused render frame 3 and the decode worker frames 4-5 (`:144-146`), so no two threads ever touch the same frame. At a real play stop with lookahead 0, the worker's in-flight recon is the last playback frame, which may be the very frame the paused render redraws. Add a same-frame case (recon worker and paused render both on one frame), or say in the PR why the frames can never coincide at stop.
- **The harness skips the production dispatch's Qt and slot layer.** It calls `renderDebayered16FromSlot` with null slot/output pointers (`:96-97`) and `setMlvCpuCores(video, 4)`. So it doesn't test the slot buffers, `m_pMlvObject` cache resets from the GUI thread, or the core mutations at stop (`selectDebayerAlgorithm`, `applyEffectiveDualIsoPlaybackSettings`). Those are still open as writer candidates; list them in the successor plan.
- **CI cost and value of the guard:** defaults of 16 (tiny) and 3 (large) iterations won't catch a race in CI. They do add a multithreaded large-fixture run to the `pipeline_tests` shards that already hit the 60-minute job cap once (Windows Product Oracles part 1/3, r2 notes). Either keep only the tiny case in CI and leave large to the stress env var, or report the shard time on the next green run.
