- Soft, CoS-verified (Codex Blocker, Claude Improvement; **not** promoted): the exclusion hole is real and points **fail-open**, but in practice it is narrow. In `Get-PresentMonProcessSnapshot` (`tools/profiling/bachelor/playback-attr-3-cuda-job.ps1:1291-1331`), a `PresentMon*` process is **excluded** (not counted live, so the sweep runs) when (i) its pid is any registered `Win32_Service` ProcessId, with the service never name-checked (`:1318-1319`), or (ii) its path is readable, it isn't the pinned name or path, and its name misses `^PresentMon([-_.]?(\d|x64|x86|console|capture|cli)|$)` (`:1303`, `:1321`). The wrong direction is "live capture treated as not live → sweep terminates its session". The opposite direction (a real orphan left unswept) only comes from fail-closed paths: an unreadable non-service process, a pinned-name helper, or a CIM/list throw → `error`, touch nothing (`:1320`, `:1445-1446`). What actually limits the harm is that the sweep only ever targets sessions named exactly `PresentMon` or `MLVAttr3-*` (`AttrCudaArtifacts.psm1:2037`):
  - **Service arm:** the owner's Intel PresentMonService creates ETW sessions named `PMService` / `PMService_ETL` (`--etw-session-name` default; `pm-child-etw-session` as child; upstream `GameTechDev/PresentMon` `IntelPresentMon/PresentMonService/CliOptions.h`, `EtwLogger.cpp`). Those names are never sweep targets, so exempting the service can't stop its capture on Bachelor.
  - **Harness captures:** every harness capture runs the pinned image (always live via `pinned_image_name`, `:1315`), and other pinned versions (`PresentMon-<ver>-x64`) match the capture pattern. A concurrent or other-version harness job is never excluded.
  - **What's left:** a manually launched, oddly renamed console PresentMon (e.g. `PresentMon (1).exe`, `PresentMon-dev`, `PresentMon_arm64`) at a readable path, running with the default `PresentMon` session at the moment a job starts. The sweep would terminate that manual capture's session. That is data loss for an ad-hoc owner capture, not a killed factory process and not a broken factory state. A default-named live session also already starves the harness capture of events (the original UM bug), so that run would be bad either way.
  
  Ask: either drop the readable-path exclusion (treat every non-service, non-pinned `PresentMon*` as live), or name-check the service (`Win32_Service.Name -eq 'PresentMonService'`), and add the regex boundary table plus an odd-name readable fixture.
