- **Failed quarter refresh shifts the Bayer frame twice** (confirmed at tip `e4851a9f`, line refs re-checked 2026-10-03 12:17 CT; from the Iverson advisory, where Codex rated it a Blocker and Claude an Improvement). `processingRefreshShadowsHighlightsQuarterBlurFromBayer16` (`src/processing/raw_processing.c:1984-1994`) shifts the caller's Bayer buffer in place (`bayer[i] <<= bitShift`). Only after that does it call `sh_proxy_quarter_from_bayer` (`:1997-2002`), whose per-worker `malloc` of 4 debayered rows (`:1893-1898`) sets `failed`, and the refresh then `return 0`s. `RenderFrameThread::drawFrame` (`platform/qt/RenderFrameThread.cpp:4174-4233`) treats `quarterRefreshed == 0` as "refused" and runs the full-res fallback (`:4206`). At `:4228` that fallback calls `debayerBasicU16(..., slot.rawImage16.data(), ..., bitShift)` with the same `16 - bits_per_pixel` shift, and `debayerBasicU16` shifts in place again (`src/debayer/debayer.c:460-467`). For 14-bit frames (shift 2) that means <<4 in total, which truncates every sample ≥ 2^12. It corrupts the S/H blur and the `slot.rawImage16` frame that later stages read (e.g. GPU AMaZE input, `RenderFrameThread.cpp:4494-4496`), silently and with no telemetry. Reachability: the eligibility refusals and null/size guards all return **before** the shift (`:1964-1980`), so a normal refusal is safe. The **only** path from "shifted" to "return 0" is the scratch-row allocation failure. That needs OOM (a few tens to ~130 KB per thread), so it is rare, but it is reachable, it breaks the PR's "engine refuses and the full-res path runs instead" contract, and the fix is cheap. Separately, `buffer_set_size(blur_image_half_out, …)` at `:1996` does not check its `malloc` (`:725-734`, an existing helper), so a NULL quarter buffer would crash in `sh_proxy_quarter_from_bayer` rather than fall back. Fix: allocate or check all scratch (and the quarter buffer) **before** the in-place shift, or shift on read and commit the in-place shift only on success, or return a distinct "already shifted" code so the caller passes `bitShift=0` to the fallback. Add an allocation-failure test seam with `bitShift=2` that asserts fallback picture and Bayer parity.
