## Production reasoning

### Constant-channel composition

The [real x4 route, video_mlv.c:7204–7222](https://github.com/SuperDimensionalSpaceFortress/MLV-App/blob/3cd2f1446154a51111dfac4ace89412b0c185018/src/mlv/video_mlv.c#L7204-L7222), now invokes the combined HA-CD/chroma helper before its factor-two box. It no longer calls the unrestricted chroma helper at this site.

In [debayer.c:566–606](https://github.com/SuperDimensionalSpaceFortress/MLV-App/blob/3cd2f1446154a51111dfac4ace89412b0c185018/src/debayer/debayer.c#L566-L606), an own-path output is a positive-weight mean of its channel's three taps. Otherwise the colour-difference result is clamped to those taps' own minimum/maximum. Therefore every chroma output lies within that channel's input-tap range. If all three taps equal integer C, both branches return exactly C, independent of G. Together with the preceding singleton own-Bayer range bound, this closes the previously demonstrated mechanism in the constant region whose full support remains constant. A following mean of equal C values cannot reintroduce the G edge.

This is a support-local result. Near the boundary of a constant patch, taps may include nonconstant neighbours. A range bound alone does not prove arbitrary-colour reconstruction accuracy or no-worse-than-bilinear error. The prior filter mechanism was retained relative to the older head; this review does not retroactively label it proven r11-introduced.

### Affine channel and kept-channel paths

The added [HA selector, debayer.c:757–789](https://github.com/SuperDimensionalSpaceFortress/MLV-App/blob/3cd2f1446154a51111dfac4ace89412b0c185018/src/debayer/debayer.c#L757-L789), compares own-sample curvature, scaled by the valid positive fit slope, with curvature of the already-produced colour differences. On an affine channel away from reflected boundaries, own curvature is zero, so it selects the nearest-own-sample interpolation even when colour-difference curvature is also zero. The nearest-sample mean reproduces the affine channel, subject to integer rounding. The subsequent 5x5 bound contains that interpolation. At chroma, zero own curvature likewise selects the channel's own [1,2,1]/4 instead of adding colour differences to G. For the tests' integral ramps and even slopes, these means are exact; no rounding caveat changes their asserted expected values.

At [debayer.c:570–586](https://github.com/SuperDimensionalSpaceFortress/MLV-App/blob/3cd2f1446154a51111dfac4ace89412b0c185018/src/debayer/debayer.c#L570-L586), the corresponding keep bit forces the own-channel chroma path before division. Thus a negative/otherwise rejected fit does not fall through to the old G-imprinting chroma path. HA-CD still retains that channel's input bilinear bytes; the combined operation then filters those bytes with the channel's own [1,2,1]. Do not describe the combined operation as byte-preserving for arbitrary kept channels: it is the HA step that retains bytes, while the following filter can smooth non-affine content.

Fit-output initialization is sound: [lines 655–675](https://github.com/SuperDimensionalSpaceFortress/MLV-App/blob/3cd2f1446154a51111dfac4ace89412b0c185018/src/debayer/debayer.c#L655-L675) initialize a=1 and c=0 and unconditionally assign both output pointers before returning. The new copies into sel_out before the keep==3 early return therefore do not read uninitialized values. HA selection skips each kept channel, and chroma division happens only for a clear keep bit. Valid slopes remain in [1/64,64].

The own-site selection indices are also consistent with the existing reflection invariant. Setting both row and column parity to ch selects R-even/even or B-odd/odd. The last odd-dimension correction subtracts two, preserving parity and bounds. Reflection of offsets of at most two preserves that same parity, and dimensions are at least four. New dif reads therefore address produced own sites, not G holes. Producers finish before consumers; selection and range passes write only their output row and read immutable Bayer/dif. The combined chroma stage reads the completed RGB frame and writes a separate filtered frame at the production call site. No new data race or current unwritten-site read was established.

Exact affine claims should remain bounded to the tested interior/support and quantization. Reflection at image edges need not preserve a nonzero affine slope. ## Remedy reasoning and invariants

1. [Directional HA estimates, debayer.c lines 642–665](https://github.com/SuperDimensionalSpaceFortress/MLV-App/blob/05cc2e159a844b87c51f99ea3506f938a121e936/src/debayer/debayer.c#L642-L665): each horizontal/vertical estimate is individually bounded by its two green neighbours before gradient selection. A tie averages two already-bounded estimates. The result therefore cannot overshoot the overall four-neighbour green range. This eliminates directional overshoot; it is not a general colour-error guarantee. It modifies only the internal HA estimate, not the output G plane.

2. [Fit and retention, lines 590–629 and 740–750](https://github.com/SuperDimensionalSpaceFortress/MLV-App/blob/05cc2e159a844b87c51f99ea3506f938a121e936/src/debayer/debayer.c#L590-L629): fit success requires at least 16 samples, variance strictly greater than 1, and slope in inclusive [1/64,64]. Failure now sets an independent R/B keep bit. Both invalid returns success without touching RGB; one invalid still computes both scratch colour families, but both pixel writes and the range pass skip the invalid channel. Thus there is no partial-valid uninitialized-scratch shortcut, and per-channel retention is exact. The default initialized identity coefficients remain safe for unused scratch computation. The header's wording that return 1 means R and B “were rebuilt” is now imprecise: success can mean one or both were retained, as its surrounding documentation acknowledges.

3. [Own-channel range pass, lines 704–738](https://github.com/SuperDimensionalSpaceFortress/MLV-App/blob/05cc2e159a844b87c51f99ea3506f938a121e936/src/debayer/debayer.c#L704-L738): row and column start parity select only R-even/even or B-odd/odd samples in the 5×5 window. Reflection i→−i or i→2(n−1)−i preserves parity for even and odd dimensions; offsets are at most two, and minimum accepted dimensions are four, so one reflection suffices. Each channel has a nonempty 2-or-3 by 2-or-3 sample set. If all those channel samples equal C, lo=hi=C and rebuilt output is exactly C regardless of green structure. A degenerate channel is not clamped, preserving its bilinear bytes.

4. [Producer/consumer loops, lines 751–801](https://github.com/SuperDimensionalSpaceFortress/MLV-App/blob/05cc2e159a844b87c51f99ea3506f938a121e936/src/debayer/debayer.c#L751-L801): producers still initialize every R/B scratch site and consumers access only those parity families. The two OpenMP loops have a completion boundary; the added range operation runs after reconstruction within the same output row, reads immutable Bayer, and writes no other row. G is never written by either new operation. This supports the existing thread-independence argument. It is not an executed thread test. The production entry/call site is unchanged in this three-file delta, so no new x2/full-resolution routing change is introduced.
