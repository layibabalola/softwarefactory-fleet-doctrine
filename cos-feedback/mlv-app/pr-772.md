Regression plan: custom root containing a canceled trailing-dot or space segment must add the resolved custom bin before default fallback; add canceled semicolon/quote cases only where supported by the intended Windows lexical semantics. Surviving semicolon/quote/reserved-character segments must remain rejected, and emitted PATH must contain no unintended relative entries. Existing exact spelling, Unicode, root-parent, slash, duplicate, and no-filesystem checks must stay intact. No such tests were executed by this reviewer.

## Boundary and risk assessment

1. Child-only mutation is supported by source. The new call is inside the Codex branch and changes `ProcessStartInfo.Environment`, not caller `$env:PATH`; Claude branch is untouched. The function reads only the configured MINGW_ROOT value plus the child's existing PATH. No credential read or network API is added. Source: https://github.com/SuperDimensionalSpaceFortress/MLV-App/blob/071338fa0ace74824763466b82e46cbc97fc149c/tools/coordination/Invoke-Lane.ps1#L2817-L2828 . New logging exposes added directory strings to lane output; it does not log the entire inherited environment.

2. Candidate gates prevent directly serializing relative paths, explicit UNC paths, semicolons, and quotes into added entries. Exact ordinal keys avoid culture-fold collisions; only drive-letter case is folded. Inspection confirms no filesystem lookup or thread/runspace in the helper. These are useful containment properties, not proof that a selected directory is trusted or locally backed.

3. PATH is broader than a two-DLL allowlist. Appending both configured and default toolchain bins makes every otherwise unresolved executable and PATH-searched DLL in those directories discoverable by the Codex child and inheriting descendants. Existing PATH entries retain their relative precedence; appended entries do not displace an earlier incompatible DLL or override application-directory/system loader precedence. This is an inherent design tradeoff, not a proven exploit. Document trusted-toolchain assumptions and regression-test existing executable resolution and incompatible earlier runtime scenarios in an authorized Windows validation setting. Source: https://github.com/SuperDimensionalSpaceFortress/MLV-App/blob/071338fa0ace74824763466b82e46cbc97fc149c/tools/coordination/Invoke-Lane.ps1#L1982-L1984 and #L2030-L2046 .

4. No-filesystem helper does not imply no downstream filesystem/network activity. Drive-letter paths can name mapped drives or paths through junctions. Appending them defers probing to downstream command/DLL searches; those consumers could still stall on an unavailable backing target. This is a residual limitation to characterize, not evidence this helper stalls. Do not restore blocking existence checks as a superficial remedy.

5. The regression seam executes the extracted helper against ProcessStartInfo and asserts string output. It does not prove sandbox environment inheritance or actual DLL compatibility. Runtime seam tests are skipped off Windows or without pwsh.
