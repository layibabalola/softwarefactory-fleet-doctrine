- **SHARED Blocker (both models) → downgraded to Soft (Improvement)** after CoS checked the code and the job model. **The defect is real in code:** in `Invoke-PresentMonOrphanSweep` (`tools/profiling/bachelor/playback-attr-3-cuda-job.ps1:1289-1343`), the two "no PresentMon alive" checks (`:1299`, `:1314`) protect only the first listing `$listed`. After the terminate loop (`:1322-1326`, up to 10 s per listed session), `$afterTerminate` is a **fresh** listing (`:1327`). `Stop-AttrCudaEtsSession` then runs `logman stop -ets` on every `PresentMon` / `MLVAttr3-*` name in it (`:1328-1333`), with no liveness recheck and no intersection with `$listed`. **But CoS found no in-fleet path that starts a competing capture inside that window, so it is not a merge Blocker:**
  - **Agent jobs on a host are serialized.** `ultra-magnus-agent.ps1:290-371` takes one inbox snapshot per poll, then for each job runs one child pwsh and waits on it (`WaitForExit` loop to its deadline, else kills the tree) before claiming the next. `um-run.ps1:64`, `:158-160` and `:335-337` record "processed sequentially", verified against both the tracked and the deployed agent. Every PresentMon user in the job set (`playback-attr-3-cuda-job.ps1`, `attr3-stage-smoke-runner-job.ps1`) runs through that queue as a direct child of the job (`:1148-1153`). So job B's sweep can't overlap job A's capture.
  - **Sessions are scoped per job** (`Get-PresentMonSessionName`, `:1257-1265`: `MLVAttr3-<job-id tail>`). A timed-out job's tree is killed by the agent, so its session is a genuine orphan for the next job. A PresentMon that survives the kill keeps the next sweep skipped (`presentmon_process_alive`), never racing it.
  - **The `MLV\PresentMonSidecar` task (default `PresentMon` name) is not used by this job** (`:1150-1153`). The tracked repo has no caller of `submit-presentmon-sidecar.ps1`.
  - **There is no host-wide mutex** around the sweep. `Global\MLVAppGuiSmokeLogParser` (`run-release-gui-smoke.ps1:1792`) is taken later, by the smoke runner, not around PresentMon. The tracked agent also has no single-instance guard.
  - **What remains is out-of-band only:** an operator or third-party tool starting a default-named `PresentMon` / `MLVAttr3-*` capture on the venue host during the seconds-long terminate window, or a misconfigured second agent instance polling the same inbox (for example, `install-ultra-magnus-agent.ps1` re-run while one is already live). Either would have its live session stopped and lose its CSV.
  - **Recommended fix (cheap; prefer before the first UM run on this tip):** limit the `logman` fallback to `$stillListed ∩ $listed`, and re-run `Get-Process 'PresentMon*'` immediately before it (skip if any is alive). If either guard ever fires, record it in the sweep record.
- Soft (both models; confirmed): the `$afterTerminate` listing's exit code is ignored. `:1336` folds `$afterTerminate.error` and `$afterStop.exitCode` into `listError`, but not `$afterTerminate.exitCode`. A failed post-terminate listing yields empty or partial text, skips the `logman` fallback, and leaves no `listError` (only `remaining` hints at it). Add `-or $afterTerminate.exitCode -ne 0`.
- Soft (Claude): the live-process guard is hardcoded to `PresentMon*` (`:1299`, `:1314`) while the binary is the `$PresentMonName` parameter. Derive the process name from `[IO.Path]::GetFileNameWithoutExtension($PresentMonName)` as well, so a renamed binary can't silently disable the guard.
