## Blockers

1. **Under/over flags diverge from the CPU scope (CoS catch).** `playbackScopeTapRgbaBottomUpToRgb8` sets `under` if any channel of any pixel is 0 and `over` if any channel is 255, and the tap feeds those into `ScopesLabel::setScope`. On master, the CPU path's flags come from `underOver`. With zebras off they are 0: `applyZebrasToImage` returns 0 when zebras are disabled (`MainWindow.cpp:18806-18811` @8bcc2b3e), and `scanZebrasRgb8` runs only when `useGpuShaderZebras` is set (`:4365-4367`). When zebras are on, `scanZebrasRgb8` uses HSL lightness against `preview_zebra::kUnder/OverThreshold8Bit` (`:18780-18799`), not per-channel 0/255. The tap only serves with zebras **off**, so the CPU scope in the same state shows no clip markers. The tap path would draw the histogram's blue/red clip squares (`Histogram.cpp:211-224`) on almost any real frame, because one black channel anywhere is enough. A GL_LINEAR downscale also means its flags would not track the CPU rule even if the rule matched. **Unblock:** pass `under=false, over=false` from the tap while zebras are off (the only state it serves). If clip markers are wanted later, reuse `scanZebrasRgb8`'s lightness rule behind the same zebra condition. Re-pin PGT-04 as a parity test against the CPU helper for the same input and zebra state, not as a new rule.
2. **The GL read-back path (R3) has zero runtime evidence.** The venue never issued a tap (`tap_requests=0`), and the GL row was not applied (hook NA-6 refused adding `QSKIP`; the patch is staged as `staged-gl-row-NA6-denied.md`). The offscreen gui_tests cannot exercise it either. Issue/poll/map/teardown, the blit Y-flip, the `cleanupGLResources` context handling and the `takeScopeTap` makeCurrent path are all unexecuted. **Unblock:** get the hub ruling on NA-6, or add the GL row as a new test file that the hook allows. Then show at least one real-GL run on a widget-viewport venue with `scope_tap_completed>0`, `scope_source=gpu_tap` and a visual scope strip.
3. **S1 unmet and r2 needs rulings, as the PR itself says.** Extending the read-back to GpuDisplayWindow reverses the ruled line "GpuDisplayWindow is NOT touched", so it needs a design ruling. Fixing the CUDA job's eligibility verdict is a harness gate change and needs its own review. Do not merge r1 as a standalone partial while those are open.

- `requestScopeTap` counts `notReady` whenever any slot is pending, even when a free slot accepts the request. Either rename it (`requests_while_pending`) or count it only when the request is dropped, so `scope_tap_not_ready` reads as dropped requests.
- `scopeTapSupportedNow()` caches on a raw `QOpenGLContext*`. `destroyScopeTapResources` resets it, which covers normal teardown. A context re-created at the same address without a cleanup pass would reuse a stale answer. Low risk; a context-destroyed hook, or keying on `QOpenGLContext::shareGroup()` plus a generation counter, would close it.
- Soft: the scope now measures the display-shaded picture (after any GL-side display transform), while the CPU feed uses `rgb8DisplaySource`. State in the card that they are expected to be equivalent with zebras off, and pin it with the parity test in blocker 1.
