## I1: no-PID cleanup may leave spawned fixture child

In factory/controller/controller.test.mjs:955–957 the fixture starts an interval-running grandchild before publishing its PID. If it stalls or the PID write fails in that interval, the parent bound can expire and readPid returns null. At 927–938 reapRealChild skips PID cleanup and kills/waits only for the direct subprocess handle; the test does not establish descendant-tree containment. Thus direct-parent exit does not prove the already-spawned grandchild exited. The test fails rather than falsely passing. Normal successful PID publication uses explicit cleanup; external OS containment could change observed behavior but is not established by this test. Static source trace, not an executed orphan reproduction or production pin-verification defect.

Inject a barrier/failure after child creation and before PID publication; assert both processes exit while preserving the original failure. Use reliable descendant ownership/containment or a bounded self-expiring fixture child, rather than treating missing PID as evidence no child exists.
