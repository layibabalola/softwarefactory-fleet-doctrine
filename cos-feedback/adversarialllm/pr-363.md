## Remedy trace and R8-C1 limitation

https://github.com/layibabalola/AdversarialLLM-ClaudeCode/blob/2b859e2a32daaa1f3b76a2c663ce925323df73f2/tools/heavy-slot/heavy-slot.ps1#L721-L762

At lines 748–750, the selected reason map's properties are materialized into $listed and copied into a new ordered map only when count <=16. The new reason is then added. A legitimate 16-entry map can grow to 17 and have its oldest member removed, preserving the existing boundary. An over-16 map on this due path is replaced by the single new reason, eliminating the former copy of every entry, full-map sorting and many individual removals. The function is shared by lastUnsure and lastWouldAt, although the new regressions exercise lastUnsure only.

R8-C1, source-proved qualification: the new validation happens AFTER Test-ReapReceiptDue at lines 738 and 743. That helper at 724–729 still reads the requested reason from any supplied map without a size check. An over-16 map containing the current reason with a recent/future timestamp therefore remains authoritative to suppress that receipt:
- With a non-null supplied state, the outer due check returns false before the cap is reached.
- With null supplied state, the state loaded inside Update-ReapState can fail the inner due check and be written back unchanged.
Thus “overlong maps are discarded when a due claim is rewritten” is supported; “overlong maps count as absent everywhere” is not. F21/F22 both pass null state and request a new absent reason, so they do not test either branch. This is not a newly introduced suppression capability: a writable 16-entry or smaller map already permits it, and future-claim suppression is an acknowledged prior limit. It is a remedy/wording boundary, not demonstrated renewed admission denial. Minimal advisory response: narrow the claim, or validate the map consistently before both due checks and add recent/future-existing-reason controls if unconditional absence is intended.

The implementation still parses the allowed-size record under Update-ReapState's shared lock (699), copies top-level properties (701), enumerates every selected map property into $listed (749), and serializes/writes retained state. It does not make work O(16) from opening to publication, and does not bound lock duration. The source comment in the proof at 693 that final survivors show the map was “not worked through” is too strong: final-state absence establishes discard behavior, not work/timing avoidance. Source inspection establishes which costly operations were removed.
