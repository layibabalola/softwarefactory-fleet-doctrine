## Blockers

- **`kcs.evidence-ui-flow-functional` calls `OpenFileDialog.ShowDialog`** — pin in `SelfTestCli.cs` creates a temp file, then calls `EvidenceAttachmentManager.TryAddEvidenceFromDialog(record)` and asserts `record.Evidences.Count > 0`. That API always pops a modal file dialog; it never receives the temp path. On `build-and-selftest` (headless / no operator) the dialog cancels or hangs, so the pin fails (or the job stalls). Rewrite the pin to attach via `EvidenceAnchor.Create(tempFile)` + `record.Evidences.Add` (and optionally call `ValidateAllEvidence`), matching how Phase 0 behavioral pins work. Keep the dialog only on the real `_btnAddEvidence` click path.

## Improvements

- **Add/Remove evidence never persists the case record** — `_btnAddEvidence` and the per-row Remove handlers mutate `_record.Evidences` in memory and refresh the panel, but never save. A Reload / case switch drops attachments. After a successful add or remove, call the same persist path other CaseRecord edits use (or mark dirty and autosave).

- **Evidence panel mixes Dock with manual `SetBounds`** — `_pnlEvidenceList` is `Dock = Fill`, then `Resize` also `SetBounds` on `_lblEvidenceCount` / `_pnlEvidenceList`. Prefer one layout model (e.g. top label + fill list, or pure manual bounds) so theme/resize stays stable.

- **`_btnAddEvidence` height 32 vs row peers at 28** — `Theme.ButtonRow` peers use Height 28; this button is 32. Match 28 for row alignment.

- **Cancel vs failure status conflated** — click handler treats any `TryAddEvidenceFromDialog` false as `"Failed to add evidence file."` Cancel (user closed dialog) is also false. Distinguish cancel (no status / quiet) from catch-path failure.

- **Phase 0 leftovers still open on main** (not introduced here, still relevant): `TryAddEvidenceFromDialog` catch still calls `AutomationHealth.Report` unguarded; `SerializeEvidenceForSoql` still ships absolute `LocalPath`; `CaseRecord.IsEmpty` still omits `Evidences` if that CRITICAL was never re-applied after #33.

- **Two new pins are structural-only** — `kcs.evidence-ui-button-exists-and-wired` / `kcs.evidence-display-panel-integrated` only reflect fields/methods. Fine as smoke; the flow pin should be the behavioral one (once dialog-free).
