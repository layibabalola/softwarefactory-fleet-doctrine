§1 | "A non-authoritative mirror copies verdicts.csv to master by private-index commit every 1 h (clock_domain=real), eight CAS attempts under the backoff above, then MIRROR_CONTENDED." | On Windows NTFS with live rclone backups, a single git CAS operation under concurrent I/O contention can exceed the 200ms reducer tick and consume backoff budget in one stall. Eight retries totaling 6.4s budget exhausts under sustained load; MIRROR_CONTENDED silently waits 1 hour with no corrective retry, leaving verdicts.csv unsynced and undetectable until next publish cycle. | REPLACES: "eight CAS attempts under the backoff above, then MIRROR_CONTENDED" → "eight CAS attempts with backoff measured against actual NTFS latency under concurrent checkpoint writes, then MIRROR_CONTENDED with exponential-decay wakeup (not 1h fixed)" | PROOF: In Cloudvore, instrument git CAS latency during rclone backup (measure via `GIT_TRACE_PERFORMANCE=1`); run mirror write 10 times; if any single CAS > 200ms, demonstrate likelihood of >8 retries under peak load; verify no mechanism wakes mirror before 1h.

§2 | "All executors are non-breakaway Job Objects with kill-on-close. The reducer alone allocates canonical Windows path sets...allocations cannot overlap." | Path fencing assumes exclusive executor control of allocated paths. Live rclone backup runs outside the executor framework and holds open handles to arbitrary checkout paths concurrently with executor writes. Spec provides no coordination mechanism between allocated-path enforcement and external processes. Executor at src/data.json and rclone backup simultaneously open the same file: fencing invariant violated. | REPLACES: "allocations cannot overlap" → "allocations cannot overlap among tracked executors; external process coordination is out-of-scope and must be configured separately (e.g., rclone exclusion patterns)" | PROOF: In Cloudvore, start executor E writing to src/ with allocated path set {src}. Launch rclone backup with `--include '*'`. Monitor with Process Monitor. Confirm both E and rclone hold open handles to overlapping files; verify spec provides no mutual exclusion or quorum mechanism.

§2 | "Before reassignment, recovery records STOPPING, terminates the whole prior Job Object including its sidecar, confirms no member remains, records {...termination_receipt}, then atomically retires the claim and releases paths; no termination confirmation ⇒ BLOCKED-TERMINATION" | "Confirms no member remains" is not operationalized: no specification of how to validate full Job Object termination or how to detect escaped processes. Windows allows zombie states and inherited handles across process boundaries. On NTFS under I/O delay, subprocess file handles held open prevent reliable confirmation. If check method is insufficient (e.g., GetProcessExitCode only on direct children), a process escapes. Spec records BLOCKED-TERMINATION, paths retained, but leaves confirmation implementation undefined. | REPLACES: "confirms no member remains" → "confirms no member remains via QueryInformationJobObject(JobObjectBasicProcessIdList) and cross-validation with tasklist /FI; timeout after 30 s terminates hung children via pssuspend64 chain" | PROOF: In Cloudvore, create executor E1 spawning child C1 with open handle to allocated path p. Reducer terminates J1. Implement confirmation check (undefined vs. robust). Does C1 report exited in first check? If not, paths blocked. Scenario: win-suspend.ps1 fails on escaped child; BLOCKED-TERMINATION triggered.

§2 | "One oracle-reduce.py instance per checkout (§7) ticks every 200 ms (clock_domain=real)...Renewal requires...verifies the claim OID and CASes the lease ref." | On Windows NTFS with live rclone, a single lease renewal CAS can take 300-500ms under backup I/O load (recorded in CLAUDE.md notes on git latency). If renewal latency exceeds 200ms, the next tick begins before prior renewal completes; if sustained latency approaches 600s RENEW window, sidecar may exit prematurely (lease_until < oracle_now - grace) before H, orphaning the executor. Spec does not bound CAS latency against tick interval or RENEW window under realistic I/O contention. | REPLACES: "ticks every 200 ms (clock_domain=real)" → "ticks every max(200 ms, measured_p95_CAS_latency + 50 ms) under production clock; RENEW window minimum 2 h (clock_domain=real)" | PROOF: In Cloudvore, measure lease renewal CAS latency 100 times during live backup with GIT_TRACE_PERFORMANCE=1. Record p50, p95, p99. If p95 > 150ms, calculate effective tick interval and validate against 600s RENEW TTL. Create scenario: inject 150ms synthetic I/O delay per CAS, run 10 renewal attempts, verify sidecar survives to H or exits prematurely (check oracle-lease-sidecar.py log).
